# firmware — 아두이노 펌웨어

토마토피커의 하드웨어 보조 제어를 담당하는 Arduino(Uno) 펌웨어 모음.

| 폴더 | 상태 | 설명 |
|---|---|---|
| **`PS2-MOTOR/`** | ✅ **현재 사용** | 메카넘 주행(PS2 수동조종) + L1 미러링 토글 + R1 모션 프리셋 통합 |
| `mecanum_serial/` | 참고용 | 젯슨이 시리얼 `G <ticks>` 명령으로 직선 이동시키는 자율주행 컨셉. ⚠️ 직결 HR8833 핀 가정 — **이 보드(PCA9685)와 안 맞아 재작성 필요** |
| `diagnostics/` | 진단용 | PS2/PCA9685 배선·부팅 문제를 좁혀나갈 때 쓰는 최소 스케치 모음. 아래 [진단 스케치](#진단-스케치) 참고 |

대상 보드: **Moebius MecanumRobot (Arduino Uno, CH340 클론)** + PS2 무선 컨트롤러.
모터는 **PCA9685(I2C)** 경유, PS2 핀은 `CLK=12 / CMD=11 / SEL=10 / DAT=13`(확정 배선,
`diagnostics/ps2_toggle`로 검증됨).

**시리얼 포트 매핑(젯슨 기준)**: `/dev/ttyUSB0` = CH340(USB VID:PID `1a86:7523`) =
이 메카넘 보드. `/dev/ttyACM0`(`1a86:55d3`)은 SO-101 팔 쪽 장치라 이 펌웨어와 무관.
`ls -la /dev/serial/by-id/`로 재확인 가능.

## PS2-MOTOR (현재 펌웨어)

한 보드에서 **본체 주행 + 팔 제어 보조**를 모두 처리한다. 주행은 아두이노가
자체적으로(PS2→PCA9685), 팔 미러링/프리셋은 **시리얼로 젯슨에 신호만** 보내고
실제 팔 동작은 젯슨([../tools/mirror_toggle.py](../tools/mirror_toggle.py))이 LeRobot으로 수행한다.

### 조작

| 입력 | 동작 |
|---|---|
| **↑ / ↓** | 전진 / 후진 (누른 동안만) |
| **← / →** | 좌회전 / 우회전 |
| **□ / ○** | 좌 / 우 평행이동(strafe) — *R1 안 누른 상태* |
| **L1** | 팔 미러링 ON/OFF 토글 → 시리얼 `TOGGLE` |
| **R1 + △/○/✕/□** | 모션 프리셋 1/2/3/4 → 시리얼 `PRESET 1~4` |

- 주행은 **누르고 있는 동안만** 이동, 떼면 즉시 정지.
- 미러링 ON에서 `R1+버튼` = 현재 팔 자세 **저장**, OFF에서 = 저장 자세 **재생**(판단은 젯슨).

### 시리얼 프로토콜 (115200 baud, 줄단위)

```
Arduino → "TOGGLE"     L1 눌림 (미러링 토글)
Arduino → "PRESET <n>" R1+면버튼 (1=△ 2=○ 3=✕ 4=□)
Arduino → "Found Controller..." / "Controller_type: N"  부팅 배너
```

### 견고성 처리 (이 보드 특유 이슈 대응)

- **PS2 핀13 노이즈**: DAT가 온보드 LED와 핀을 공유해 한 프레임 걸러 손상프레임이
  섞인다 → 버튼 7개↑ 동시눌림이면 프레임 스킵. 방향키 뗌은 2프레임 디바운스,
  프리셋/토글은 엣지검출+리프랙토리.
  ⚠️ **아날로그 4축이 모두 255/0인지로 손상을 판정하면 안 된다** — 컨트롤러가
  "디지털 모드"(아날로그 LED 꺼짐)일 땐 정상 상태에서도 4축이 항상 0xFF(255)라서
  매 프레임이 오탐되어 버튼 입력이 전혀 처리되지 않는 버그가 있었다(`diagnostics/ps2_toggle`
  주석에서 먼저 발견됨, 이후 `PS2-MOTOR.ino`에도 반영해 제거).
- **컨트롤러 무응답 시**: 원본은 `resetFunc()`로 무한 재부팅 → 제거하고 **재부팅 없이
  `config_gamepad` 재시도**.
- **폭주(래치된 PWM) 방지**: 하드웨어 워치독(`WDTO_250MS`)을 넣었었지만 `loop()`가
  정상 실행 중에도 가끔 250ms를 넘겨 **오리셋 → 반복 재부팅**이 발생해 제거했다.
  대신 손상 프레임이 **5회 연속**(≈100ms)되면 소프트웨어로 `STOP()`을 강제 호출한다
  — PS2 신호가 끊긴 채로 마지막 주행 명령이 PCA9685에 영원히 래치되는 걸 막기 위함.
  (하드웨어 워치독이 완전히 없으므로, `loop()` 자체가 진짜로 멈추는 코드 버그가
  생기면 이 방어는 못 잡는다 — 필요하면 `WDTO_1S` 등 더 긴 타임아웃으로 재도입 검토.)
- **속도**: `Motor_PWM = 2000`(100%, 전력 측정 목적으로 상향). 원래 기본값은
  `600`(약 30%)이었다 — 전류↓ → 전원 출렁임/행 빈도↓ 가 이유였으므로, 100%로 계속
  쓸 거면 **BAT(7.4~11.1V LiPo) 충전 상태/굵은 전원선**을 확인할 것. 낮추려면
  `Motor_PWM` 값만 바꾸면 된다.
- **PCA9685 I2C 무응답(hang) 주의**: 이 젯슨의 AVR 코어(`arduino:avr` 1.8.8)는 Wire
  라이브러리에 I2C 버스 타임아웃이 없다. PCA9685 전원(VCC/V+)이 안 들어오거나
  배선(Uno A4=SDA, A5=SCL)이 안 맞으면 `faboPWM.begin()`에서 **무한 대기**하며,
  부팅 시리얼 출력이 `"Find PCA9685"`조차 안 찍힌다(완전 무응답). 이럴 땐 코드가
  아니라 PCA9685 전원/배선을 먼저 의심할 것 — `diagnostics/boot_probe`로 정확한
  멈춤 지점을 확인할 수 있다.

## 빌드 / 업로드 (arduino-cli)

젯슨/PC 어디서든 `arduino-cli`로 가능. 필요한 라이브러리:

- **PS2X_lib** — github madsci1016/Arduino-PS2X
- **FaBo_PWM_PCA9685** — Moebius 키트 동봉. ⚠️ `src/`의 `*(1)*` **중복 파일 삭제 필수**
  (안 하면 ld 중복심볼 에러)

```bash
# 컴파일
arduino-cli compile --fqbn arduino:avr:uno firmware/PS2-MOTOR

# 업로드 (포트는 환경에 맞게: 젯슨=CH340→/dev/ttyUSB0, Windows=COM8 등)
arduino-cli upload -p /dev/ttyUSB0 --fqbn arduino:avr:uno firmware/PS2-MOTOR
```

> 젯슨(JetPack)에서 CH340이 `ttyUSB`로 안 잡히면 커널에 `ch341` 모듈이 없는 것.
> 소스로 빌드해 넣어야 한다(메인 [README](../README.md) 또는 배포 노트 참고).

## 진단 스케치 (`diagnostics/`)

PS2/PCA9685 배선이나 부팅 문제를 다른 컴퓨터에서도 이어서 좁혀나갈 수 있도록
정리해둔 최소 스케치들. 전부 `arduino-cli compile --fqbn arduino:avr:uno firmware/diagnostics/<이름>`
으로 빌드된다.

| 스케치 | 용도 |
|---|---|
| `ps2_probe/` | PS2 핀맵을 모르는 상태에서 흔한 배선 후보 20종을 순서대로 `config_gamepad`해보고 어느 조합이 되는지 찾는다. **이걸로 CLK=12/CMD=11/SEL=10/DAT=13 확정함.** |
| `ps2_toggle/` | 확정된 핀맵으로 L1 토글만 최소 구현. PCA9685 없이 PS2 인식 자체만 확인할 때 씀(모터 드라이버 초기화가 없어 I2C 문제와 분리해서 테스트 가능). |
| `ps2_stream/` | 매 100ms 버튼/아날로그 값을 그대로 시리얼에 스트리밍. 컨트롤러가 디지털/아날로그 모드인지, 손상 프레임 빈도가 얼마나 되는지 눈으로 확인할 때 씀. |
| `ps2_diag/` | 눌린 버튼 이름을 사람이 읽기 쉽게 출력 + 1.5초마다 아날로그 하트비트. `corrupt=` 플래그로 "디지털 모드에서 4축이 항상 255"인 현상을 실제로 확인한 스케치. |
| `boot_probe/` | `setup()` 단계마다 `BOOT0`~`BOOT6` 표식을 찍어서, PCA9685 I2C 초기화(`faboPWM.begin()`)에서 멈추는지(hang) 정확히 짚어낸다. `BOOT2` 이후가 안 찍히면 PCA9685 전원/배선 문제. |

## 원격(젯슨) 접속 메모

실물 로봇은 **같은 로컬 네트워크(192.168.0.x)**에 있는 젯슨 Orin Nano에서 구동된다.
SSH 계정은 `server`이고, IP는 DHCP라 바뀔 수 있어 고정 기록하지 않는다(공유기 관리
화면이나 젯슨에 모니터 연결해 `ip addr`로 확인). **비밀번호는 이 저장소에 커밋하지
않는다** — 필요할 때 팀 내에서 별도로 공유할 것.

시리얼 포트를 열 때마다(=Uno가 DTR로 리셋될 때마다) `setup()`의 `IO_init()`→`STOP()`이
다시 실행되어 모터가 정지한다. 그래서 "폭주 중 응급 정지"가 필요하면 그냥 시리얼
연결을 한 번 열었다 닫는 것만으로도(예: `python3 -c "import serial; serial.Serial('/dev/ttyUSB0',115200)"`)
즉시 멈출 수 있다.

라이브 시리얼 모니터링은 젯슨에서:

```bash
arduino-cli monitor -p /dev/ttyUSB0 -c baudrate=115200
```

(동시에 다른 프로세스가 같은 포트를 열면 데이터가 양쪽으로 나뉘어 둘 다 지저분하게
보이니, 모니터링 중엔 다른 스크립트로 포트를 건드리지 말 것.)
