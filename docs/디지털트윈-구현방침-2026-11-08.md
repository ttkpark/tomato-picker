# 디지털 트윈 구현방침 (2026-11-08 · PM 보고 내용으로 전면 개정)

**한 줄**: 실기 팔(SO-101) 옆에 **3D 가짜 로봇(트윈)** 을 하나 더 두고, 명령을 먼저 거기서 돌려 본 뒤 **그대로** 실기로 보낸다.
첫 적용 과제 = 용용이 「제본 코일 자동화 셀 개발계획서 v0.3」(2026-10-30). 1차 = 목요일 11/12.
PM 보고 원문 = 다른 세션 보고(2026-11-08), 제안서 페이지 = https://claude.ai/artifact/1d7bFzFeXXQVA55sqC4k1J

## 1. 가상↔실기 동기화 원칙 (보고 그대로)

1. **약속은 하나.** 트윈은 실기 조작대([`click_server.py`](../ros2/tools/click_server.py), 젯슨 :8090)와 **똑같은 주소·JSON**을 받는다. 보내는 쪽(용용이 Claude/MuJoCo 순서)은 상대가 가짜인지 진짜인지 몰라도 된다.
2. 명령 = `POST /run {job, args}` 하나(`/api/run` 별명, **실기에 이미 있음**). 도는 중 새 일은 409. 상태 = `GET /state`(손끝 오차 mm·사이클 초 등). 멈춤 = `POST /stop`.
3. 트윈 팔 = [`arm_twin.py`](../ros2/tools/arm_twin.py) 준정적 모형(중력 처짐 K + 정지마찰 f + 틱 분해능, 11/08 맞춤 **K=28 f=0.2**, 후향 3/5). **실기 도구 코드는 안 고치고 FollowerIO만 바꿔 끼운다.**
4. 좌표·보정은 기존 라이브러리 그대로(`kinematics` `cartesian` `handeye` `eye.EyeConfig`). 보정 파일 한 벌을 트윈과 실기가 같이 읽는다.
5. 트윈과 실기의 차이를 **손끝 오차 mm**로 늘 표시. 트윈에서 끝까지 성공한 명령만 실기로 보내는 **승인 단계**.

## 2. 어떻게 — "트윈 = 실기 조작대를 PC에서 가짜 팔에 물려 그대로 띄운다"

따로 가짜 서버를 짓지 않는다. 같은 `click_server.py`가 돌므로 주소·JSON·409·3D 미리보기(`k3d*`)·로그가 **구조적으로** 같다.

| 파일 | 역할 |
|---|---|
| `ros2/src/tomato_bridge/tomato_bridge/twin_io.py` | 가짜 FollowerIO. 상태는 `~/twin_arm.json`에 남겨 **자식 프로세스(도구)끼리 한 팔을 공유**. 읽을 때마다 `~/arm_pose_view.json`(실측각·지령각·TCP·err_mm·twin=true)을 쓰고 `~/twin_log.jsonl`에 시계열을 남긴다 |
| `follower_io.py` 끝 2줄 | `TOMATO_TWIN=1`이면 `FollowerIO`를 twin_io 것으로 바꿔 끼움 — 도구 26개가 전부 이 한 줄을 지나므로 한 곳 |
| `arm_calib.py` | `TOMATO_CAL`/`TOMATO_CART` 환경변수로 보정 파일 자리 지정(PC에는 lerobot 캘리 경로가 없다) |
| `click_server.py` | ① Windows에서도 도는 Popen/stop ② `/state`에 `tcp` `tcp_err_mm` `twin` ③ `/bin/sh` 체인 일(park·release)은 Windows 트윈에서 명시 거절 |
| `ros2/tools/twin_server.py` | 한 줄 실행: 환경변수·보정 파일 준비 → `click_server.main()`. `python ros2/tools/twin_server.py --port 8090` |

실기 쪽은 ②③만 바뀌고 동작은 같다(젯슨은 posix·`TOMATO_TWIN` 없음).

## 3. 명령(job) — 셀용 (11/9 용용이와 이름 확정)

지금 있는 것: `pose` `stage{target}` `jog{dx,dy,dz,along,horiz,pitch,grip,piece}` `grip{value}` `yaw{deg|home|read}` `extend` `park` `release`.
추가(11/10, `ros2/tools/cell_jobs.py` 하나, 장면은 `~/cell_scene.json`): `pick{from:"exit"}` → `flip{tilt_deg:-40}` → `nest{onto:"A",cam_fix:2}` → `place{row,slot}` → `push{mm:8}`.
`/state`에 더함: `cycle_s`(마지막 일 걸린 초), `cam_fix`(재측정 횟수, 트윈은 흉내), `tcp_err_mm`.

## 5. 셀 장면 (트윈 3D에 올릴 것, 11/10)

ㄷ자 철 부품 25×15벽×300mm · 턱 높이 30mm 가운데 70mm 비움(손목 −40° 채택) · 겹치기 75mm 위 카메라 2회, 벽 끝 3mm 맞물림 · 박스 350×300×120(안 340×290×115) 8쌍×7층=56쌍, 8mm 밀기(바닥 위 8.5mm, 패드 9mm) · 잡는 힘 1.0N·m · 사이클 시뮬 22초/쌍, 목표 10(좋음)/20(마지노선) · 5축 한계: 탁자 근처 집게 90° 못 넘김, 부품은 팔 평면에 수직.

## 7. 한계 (알고 쓴다)

트윈 숫자는 실기 결과가 아니다(판정은 실기로만). 뒤집기의 마찰·탄성·끼워짐 물리는 모형에 없다. 서보 토크·전원·검출기·브래킷 유격도 없다. 트윈의 `time.sleep`은 실시간이라 사이클 초가 실기와 비슷하게 걸린다(빨리 돌리려면 checkpoint_sim의 가짜 시계).
