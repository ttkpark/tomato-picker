# 공간 지도 — 집 안 다니기 (2026-10-22~)

조작대(`http://<젯슨IP>:8090/`) 왼쪽 **[공간 지도 — Astra 3D]** 카드. 코드 = [`ros2/tools/space_map.py`](../ros2/tools/space_map.py)
(numpy만), 화면 = `click_server.py`의 `/space`·`/space/plan`·job `space`.

| 버튼 | 하는 일 |
|---|---|
| 한 장 담기 | 안 움직이고 지금 Astra 한 장을 지도에 넣는다(지도가 비었으면 그 자리가 원점) |
| 제자리 한 바퀴 스캔 | 회전 넛지 → 맞춤 → 지도에 더하기를 360°까지. 넛지 한 번이 몇 도였는지 기록에 찍힌다 |
| 바닥 클릭 → 목표로 가기 | A*로 길을 짜고(노랑), 넛지 한 번마다 다시 맞추고 다시 짠다. 20cm 안이면 도착 |

명령줄도 같다: `space_map.py snap|scan|go --x --y|clear|selftest`.

## 차체 IMU (2026-10-22~)

MPU6050을 젯슨 40핀 I²C(버스 7, 0x68)에 달았다. 발행기 = [`tools/imu_yaw.py`](../tools/imu_yaw.py)
(systemd `imu-yaw`, stdlib만) → `/dev/shm/imu.json` 50Hz. 조작대 카드 아래 줄에 **누적 회전·각속도·정지 여부**가
실시간으로 뜨고, 3D 차체가 지도 자세 뒤의 회전만큼 실시간으로 돈다(`GET /imu`).

- **θ 짐작 = 마지막 자세의 θ + 그 뒤 IMU가 잰 회전**, 맞춤은 그 둘레 ±5°만 찾는다 → 곧은 벽 모호함이 없다.
  지도가 장을 거절해도 θ는 IMU가 지킨다. 손으로 돌려 놓고 [한 장 담기]해도 각도를 안 적어도 된다.
- **회전 넛지는 시간이 아니라 각도로 끊는다**(`--deg`, 화면 "회전 목표°"). 정지마찰로 같은 지령이 0°도 40°도
  되던 병을 IMU가 닫는다. 끝까지 0.5° 미만이면 "지령은 나갔는데 안 돌았다"를 기록에 찍는다.
- 영점은 멈출 때마다(0.5초 창 흔들림 < 0.3°/s) 다시 잰다. 칩이 **뒤집혀** 붙어 있어도(지금 그렇다) 중력 방향에
  사영하니 부호는 저절로 맞다.
- ⚠ **I²C 깨진 샘플 하나 = 1.25°**(꽉 찬 250°/s × 5ms). 처음엔 레지스터 지정·읽기를 따로 해서 정지 중 계단이
  쌓였다(5분에 −8.6°). `I2C_RDWR` 한 트랜잭션 + 튐 거르기 후 0.
- 스케일: 스캔 중 `IMU 스케일: 지도/IMU = …`가 찍힌다. 1에서 3% 넘게 다르면 `imu-yaw.service`의 `IMU_SCALE`에 곱한다.
- **제자리 한 바퀴(IMU 있을 때)는 걸음마다 맞추지 않는다** — θ=IMU·자리=그대로로 장을 모으고, 한 바퀴 넘게(+50°) 돈 뒤
  처음 50°의 장과 다시 본 장들을 맞춰(고리 닫기) **IMU 스케일을 재고 지도를 다시 짓는다**. 기록에 `참 회전 = IMU × k`가
  찍히고, 1에서 0.5% 넘게 다르면 `IMU_SCALE`에 곱하라고 알려 준다. 걸음 수는 한 바퀴가 될 때까지 자동으로 는다.
- 모의(`ros2/tools/space_map_sim.py`, PC 40초) — 복셀이 참 표면 7.5cm 안에 든 비율:

  | 방식 | 복셀 | 장애물 칸 | 끝 θ 오차 |
  |---|---|---|---|
  | IMU 없음(예전) | 17% | 21% | −45° |
  | 걸음마다 맞춤 + IMU 짐작 | 37~43% | 31~40% | 0~2° |
  | **IMU + 고리 닫기(지금)** | **82~93%** | **95~100%** | **≤3.4°** |
  | 참 자세(천장) | 97% | 100% | 0 |

- ⚠ **조리개 미끄럼**(고쳤다): 처음 보는 쪽 벽 점을 아는 벽에 얹으려고 맞춤이 걸음마다 탐색 한계(15cm)까지
  미끄러졌다 — 잡음 0·θ 정확에서도. 짐작 자리에서 지도가 모르는 칸에 떨어지는 점은 맞춤에서 뺀다(selftest ⑥).
- 목표로 가기도 모의로 돈다(`SIM_GO="1.8,-0.8" python ros2/tools/space_map_sim.py`) — 한 바퀴 스캔 뒤 2m 남짓 가서
  참 자리 기준 목표까지 0.11~0.21m(허용 0.2), 지도 자세 오차 0.07~0.11m. 맞춤엔 짐작에서 멀수록 깎는 `NEAR`(칸²당 0.05점)를 줬다
  — 벽을 따라 0.19m 튀었다 돌아오며 좌우로 흔들린 걸 본 뒤.
- ⚠ **`/dev/shm` 파일이 사라진다** — server의 마지막 SSH가 끊기면 logind `RemoveIPC`가 지우는 것으로 본다(Linger=no).
  IMU 발행기는 견디게 고쳤다(19:48에 한 번 죽어 yaw가 0부터). 다른 발행기도 같은 오류가 2번 — 근본은
  `sudo loginctl enable-linger server`(아직 안 함).
- **yaw는 발행기가 켜진 뒤의 상대값**이다. 발행기가 다시 켜지면(boot가 다르면) 지도는 IMU 기준을 버리고 한 장은 예전처럼 맞춘다.

## 어떻게 (관련 연구에서 고른 것)

| 문제 | 표준 해법 | 여기서 |
|---|---|---|
| 깊이 → 2D 장애물 | `depthimage_to_laserscan` | 바닥 위 5~90cm 띠를 0.5° 부채살마다 가장 가까운 점으로 접는다 |
| 엔코더 없이 자세 | Hector SLAM(Kohlbrecher 2011), 상관 스캔매칭(Olson, ICRA 2009) | 지도 우도장에 대해 (x,y,θ) 전수 탐색(5cm·1°). **넛지가 얼마나 갔는지 지도가 말한다** |
| 점유 지도 | 로그오즈 격자 / OctoMap(Hornung 2013) | 2D 로그오즈 5cm × 15m + 3D는 5cm 복셀(확률 없이 본 표면만) |
| 길 | Nav2 costmap + 플래너 | 장애물을 차체 반지름만큼 부풀린 A*, 모르는 칸은 1.5배 비용 |
| 큰 집·고리 닫기 | RTAB-Map(Labbé 2019), cuVSLAM | **아직 없다** — 아래 다음 단계 |

## 한계 (알고 쓴다)

- **바닥이 안 보인다** — 마루가 IR을 비껴 반사해 화면 아래 절반 깊이가 0(실측). 빈 칸은 광선으로만 칠한다.
- **60cm 안을 못 본다** — 가까운 장애물은 멀리서 봐 둔 지도로만 피한다. 새로 놓인 물건이 60cm 안에 있으면 모른다.
- **화각 58°** — 회전 넛지 한 번이 30°를 넘으면 겹침이 모자라다. 기록의 "넛지 한 번 = N°"가 20° 안팎이 되게 회전 초를 줄여라.
  판정(2026-10-22 고침): **처음 보는 곳은 안 센다** — 일치율 = 맞은 점/(맞은 점 + 지도가 빈 곳이라 아는 칸에 떨어진 점) ≥ 0.6, 겹친 점 ≥ 20.
- **곧은 벽 한 토막은 어디에나 맞는다** — 15° 넘게 떨어진 다른 방향이 90% 넘게 맞으면 **모호로 거절**한다.
  손으로 돌려 놓았으면 [손으로 돌린 각도]를 적고 [한 장 담기](그 둘레 ±45°만 찾는다). 비우면 전 방향을 찾는다.
- **고리 닫기 없음** — 방 하나·짧은 거리용. 오래 다니면 표류한다.
- **장착값은 CAD 추정**(렌즈 높이 15cm, 회전중심→렌즈 12cm, 기울기 0). 실측해서
  `~/space_mount.json`에 `{"h":0.16,"x":0.11,"tilt_deg":0}`처럼 덮는다. 높이가 틀리면 바닥 위 5cm 문턱이 어긋난다.
- 3초에 한 걸음꼴(보드 열기·정착·새 프레임) — 빠르지 않다.
