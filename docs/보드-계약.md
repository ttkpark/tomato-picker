# 보드 계약 v2 — 젯슨 ↔ 주행 보드

> **이 문서의 목적 하나:** 주행 보드를 **교체할 수 있게** 만든다.
> Uno(개루프)든 STM32(폐루프)든 시뮬레이터든, 이 계약을 만족하면 젯슨 코드를
> **한 줄도 고치지 않고** 갈아끼울 수 있다.
>
> 상태: **초안(2026-08-22)**. 구현 전에 결정 항목(§14)을 먼저 닫을 것.
> 관련: [`firmware/mecanum_stable/`](../firmware/mecanum_stable/) ·
> [`hardware/motor_link.py`](../src/tomato_picker/hardware/motor_link.py) ·
> [`hardware/base.py`](../src/tomato_picker/hardware/base.py)

---

## 1. 왜 이 문서가 필요한가

지금 젯슨은 보드에 **`V vx vy w`(duty, -255..255)** 를 보낸다. duty는 물리량이 아니라
**그 보드의 구현 세부사항**이다. 그래서 이런 일들이 일어났다:

- 같은 duty가 배터리 전압에 따라 다른 속도를 낸다 → "문턱 90"이 아침저녁으로 다르다
- 게인을 만지기 전에 크기를 재야 하는데, 잴 단위가 없다 → 하루에 같은 병이 세 번
  ([CLAUDE.md](../CLAUDE.md) "1번 병")
- 보드를 바꾸면 duty의 의미가 바뀌므로 **위쪽 코드가 전부 무너진다**

계약을 물리 단위로 정의하면 셋 다 사라진다. `350mm/s`는 어느 보드에서도 같은 뜻이다.

## 2. 설계 원칙 4개

### ① 경계를 넘는 것은 물리량뿐이다

| 오가는 것 | 단위 | 표현 | 금지 |
|---|---|---|---|
| 직진/횡이동 속도 | **mm/s** | 정수 | ~~duty~~ |
| 회전 속도 | **mdeg/s** (밀리도/초) | 정수, 1000 = 1°/s | ~~duty, rad~~ |
| 거리 | **mm** | 정수 | ~~tick, px~~ |
| 각도 | **mdeg** | 정수 | ~~rad~~ |
| 전압 | **mV** | 정수 | ~~ADC 카운트~~ |
| 전류 | **mA** | 정수 | ~~ADC 카운트~~ |

duty·tick·px는 **보드 내부에만** 존재한다. 계약을 넘어오면 안 된다.

> **왜 rad이 아니라 mdeg인가.** [`line_drive.py`](../src/tomato_picker/hardware/line_drive.py)와
> 대시보드가 이미 전부 도(°) 단위로 각을 다룬다(`align_yaw_tol`, 마커 기울기).
> 여기만 rad을 쓰면 경계마다 변환이 끼고, 변환이 끼는 곳마다 부호 실수가 난다.
>
> **왜 실수가 아니라 정수인가.** 시리얼 파서를 가볍게 유지하고(AVR에서 `%f`는
> 비싸다), 값이 텍스트로 왕복해도 **비트가 하나도 안 바뀌게** 하려는 것이다.
> 소수점이 필요한 곳은 ×1000 고정소수점으로 표현한다.

### ② 보드가 자기 능력을 스스로 말한다

부팅 직후 보드는 `cap` 한 줄을 뱉는다(§6). 젯슨은 그걸 보고 **자기 기능과 화면을 켠다.**
`closed_loop=0`이면 PID 슬라이더를 숨기고, `vin=0`이면 전압 그래프를 안 그린다.

이게 교체 가능성의 실체다 — **조건 분기가 코드 전체에 흩어지지 않고 `cap` 한 곳에 모인다.**

### ③ 모르는 것은 명확히 거절한다

지원하지 않는 명령은 **`nak unsupported C`** 로 거절한다. 조용히 무시하면
*"성공했다고 말한 뒤 아무 일도 안 일어난다"* — 이 프로젝트가 이미 여러 번 겪은
가장 비싼 실패 양식이다([`cartesian.py`](../src/tomato_picker/hardware/cartesian.py)가
팔에서 이미 이 원칙을 지키고 있다).

### ④ 각 층은 위층이 사라져도 안전측으로 떨어진다

데드맨 계층(§9)은 계약의 일부다. 구현이 바뀌어도 **시한은 바뀌지 않는다.**

## 3. 계층과 책임

| 층 | 담당 | 주기 | 실시간성 |
|---|---|---|---|
| **젯슨** | *무엇을* — 인식·경로·정렬 FSM·수확 대본 | 10~30Hz | 비실시간 OK |
| **보드** | *얼마나* — 엔코더·속도 PID·슬루·데드맨·믹싱 | **500Hz~1kHz** | 경성 실시간 |
| **드라이버** | 전류·전압 | PWM 20kHz | 하드웨어 |

**메카넘 믹싱은 보드 쪽이다.** 젯슨은 차체 속도(vx, vy, w)만 말하고, 바퀴로 나누는
것과 바퀴별 PID는 보드가 한다. 그래야 베이스를 4륜 메카넘에서 다른 것으로 바꿔도
젯슨이 안 바뀐다.

> **왜 PID가 젯슨이 아닌가.** 이미 한 번 배운 교훈이다 —
> [`config.py`](../src/tomato_picker/config.py)에 *"파이썬이 0.5초 램프를 직접
> 만들어 보냈는데, 젯슨이 바쁘면 그 램프가 지터를 타서 오히려 전류가 튀었다.
> AVR이 5ms 틱으로 걸면 매끄럽다"* 고 적혀 있다. 실측 지터는
> [`linkmon.py`](../src/tomato_picker/voice/linkmon.py) 주석에 있다 — **80ms 명령이
> 40~120ms로 벌어진다.** 슬루에서 실패한 것이 PID에서 성공할 리 없다.

## 4. 프레이밍 — 기존 방식을 그대로 계승한다

```
<페이로드>*<XOR 체크섬 2자리 대문자 HEX>\n
```

- 체크섬은 페이로드 전 바이트의 XOR. 예: `C 350 0 0*55`
- **한 번 정상 체크섬을 받으면 그 뒤로 무체크섬 구동 명령은 거부한다**(`nak nocrc`).
  현행 펌웨어의 `strictCrc`와 동일하며, 계약으로 승격한다.
- baud 115200, 8N1, 라인 단위.
- **구동 명령(`V`/`C`)에는 응답하지 않는다.** 50Hz로 들어오는 지령마다 되쏘면 TX
  버퍼가 차서 loop가 막힌다(v1에서 실제로 겪음).

## 5. 명령어

### 5.1 구동

| 명령 | 형식 | 단위 | 응답 | 비고 |
|---|---|---|---|---|
| `C` | `C vx vy w` | mm/s, mm/s, mdeg/s | 없음 | **주 구동 명령.** 폐루프면 PID, 개루프면 캘리브레이션으로 duty 환산 |
| `V` | `V vx vy w` | duty −255..255 | 없음 | **레거시.** `cap`에 `units=0`인 보드 및 진단용. 새 코드는 쓰지 말 것 |
| `S` | `S` | — | `ok S` | 정지(슬루 무시, 즉시 0) |
| `X` | `X [0\|1]` | — | `ok X <n>` | **비상정지 래치.** `X 1`=걸기(가능하면 하드웨어 차단도), `X 0`=해제. 걸린 동안 `C`/`V`는 `nak estop` |

`C`와 `V`는 **마지막에 온 것이 이긴다.** 섞어 쓰지 말 것.

### 5.2 설정 — 전부 정수, 저장은 `E`로 확정

| 명령 | 형식 | 의미 |
|---|---|---|
| `G` | `G i kv ks kp ki` | 바퀴 `i`(0..3, `-1`=전체)의 게인. 전부 ×1000 고정소수점 |
| `N` | `N i cpr dia_um` | 바퀴 `i`의 엔코더 CPR(4체배 후 1회전 카운트)과 바퀴 지름(μm) |
| `M` | `M lx_um ly_um` | 메카넘 기하 — 중심에서 바퀴까지 x/y 거리(μm) |
| `L` | `L a b c d` | 바퀴 극성 ±1 (현행 유지) |
| `R` | `R accel decel` | 슬루 — 틱당 변화 상한 (현행 유지) |
| `P` | `P n` | duty 상한 (현행 유지) |
| `F` | `F hz` | PWM 주파수 (현행 유지) |
| `B` | `B ratio_x1000 lo_mv` | 전압 분압비와 저전압 경고 문턱 |
| `E` | `E [0]` | 인자 없으면 현재 설정을 **비휘발성에 저장**, `E 0`이면 지우고 공장초기값 |

> **왜 `E`(저장)가 따로 있는가.** 설정을 즉시 저장하면 튜닝 중 잘못 넣은 값이
> 영구히 남는다. 지금은 "넣어보고 → 돌려보고 → 마음에 들면 저장"이 필요하다.
> 그리고 저장된 캘리브레이션은 **보드를 옮기면 따라온다** — 이게 정석이다(§8).

### 5.3 조회

| 명령 | 응답 |
|---|---|
| `Q` | `cap ...` 한 줄 (§6) |
| `?` | `st ...` 현재 설정·상태 덤프 + `boot ...` 리셋 원인 보고 |
| `W` | **워치독 자가진단** — 일부러 loop를 멈춘다(현행 유지). 계측이 실제로 동작하는지 확인하는 유일한 방법 |
| `T` | `T i d` — 바퀴 `i`를 방향 `d`로 1초 구동(모터 배선 확인, 현행 유지) |

### 5.4 `nak` 코드

| 코드 | 의미 | 젯슨의 대응 |
|---|---|---|
| `crc` | 체크섬 불일치 | 카운터만 증가. 늘어나면 배선/노이즈 |
| `nocrc` | strict 전환 후 무체크섬 구동 명령 | 클라이언트 버그. 로그 |
| `unsupported` | 이 보드가 모르는 명령 | **`cap`을 다시 읽는다.** 해당 기능을 끈다 |
| `range` | 값이 허용 범위 밖 | 사용자에게 표시 |
| `nocalib` | 캘리브레이션 없이 `C`를 받음 | **화면에 "영점 필요" 배너.** `V`로 조용히 폴백하지 않는다 |
| `estop` | 비상정지 래치 중 | 해제 버튼 안내 |

## 6. 능력 선언 (`cap`)

부팅 직후 자동으로 한 번, 그리고 `Q`를 받을 때마다 발행한다.

```
cap proto=2 fw=3.0.0 board=stm32f411 id=A3F2C918 drive=mecanum wheels=4
    units=1 closed_loop=1 enc=4 calib=1
    vmax=800 vymax=600 wmax=180000
    vin=1 amp=1 estop_hw=1 pwm_hz=20000
```

| 필드 | 뜻 | 젯슨이 이 값으로 하는 일 |
|---|---|---|
| `proto` | 계약 버전 | 다르면 **연결을 거부하고 화면에 알린다.** 추측하지 않는다 |
| `fw` / `board` / `id` | 펌웨어·보드 종류·개체 고유 ID | 캘리브레이션 파일을 `id`로 고른다(§8) |
| `units` | 1=물리 단위(`C`) 지원 | 0이면 `V`(duty)로 폴백하고 **화면에 "개루프" 배지** |
| `closed_loop` | 1=엔코더 폐루프 | 0이면 PID 슬라이더를 숨기고 `act=`를 신뢰하지 않는다 |
| `enc` | 엔코더 채널 수 | 0이면 실측 속도 그래프를 안 그린다 |
| `calib` | 1=유효한 캘리브레이션이 저장돼 있음 | 0이면 `C`를 안 보내고 **캘리브레이션 화면으로 유도** |
| `vmax`/`vymax`/`wmax` | 물리 상한 (mm/s, mm/s, mdeg/s) | **슬라이더 범위를 여기서 만든다.** 코드에 상수로 박지 않는다 |
| `vin`/`amp` | 전압·전류 측정 지원 | `/diag` 그래프와 전압 예산 감시를 켠다 |
| `estop_hw` | 하드웨어 비상정지 지원 | 0이면 "소프트 정지뿐"이라고 표시 |
| `pwm_hz` | 현재 PWM 주파수 | 소음 튜닝 패널 |

### 구형 펌웨어와의 하위호환

**연결 후 3초 안에 `cap`이 오지 않으면 `proto=1` 레거시로 간주**하고, 젯슨에
내장된 프로파일을 쓴다:

```
cap proto=1 board=uno-moebius units=0 closed_loop=0 enc=0 calib=0
    vmax=0 wmax=0 vin=0 amp=0 estop_hw=0
```

즉 **현행 Uno 펌웨어를 한 줄도 안 고쳐도 새 젯슨 코드가 돈다.** 그 상태에서는
`V`(duty) 경로로 동작하고 화면에 "개루프" 배지가 뜬다.

## 7. 하트비트 — 1초마다, 형식은 확장

```
hb <ms> rx=<n> bad=<n> i2c=<n> wdt=<n> st=<hex>
   tgt=<vx>,<vy>,<w> act=<vx>,<vy>,<w> vin=<mV> amp=<mA>
```

- `ms` — 보드 uptime. **되감기면 재부팅**([`motor_link.py`](../src/tomato_picker/hardware/motor_link.py)의
  `_note_board_restart`가 이미 이걸 본다)
- `rx`/`bad` — 링크 품질 (현행 유지)
- `i2c`/`wdt` — I2C 물림·워치독 근접사고 (현행 유지). **PCA9685를 안 쓰는 보드는 0 고정**
- `tgt`/`act` — **지령 vs 실측.** `cap.closed_loop=0`이면 `act`는 생략
- `vin`/`amp` — 전원. `cap.vin=0`이면 생략
- `st` — 상태 비트

| 비트 | 뜻 |
|---|---|
| 0 | 비상정지 래치 |
| 1 | 소프트 데드맨 작동 중(감속) |
| 2 | 하드 데드맨 작동 중 |
| 3 | 캘리브레이션 유효 |
| 4 | 드라이버 폴트(nFAULT 등) |
| 5 | 출력 포화 (PID가 상한에 붙음 = 게인/전원 문제 신호) |
| 6 | 저전압 경고 (`B`의 문턱 아래) |

> **`tgt`/`act`가 왜 계약인가.** 이 둘이 있으면 `/diag` 화면에 **지령과 실제를 겹쳐
> 그릴 수 있다.** [`linkmon.py`](../src/tomato_picker/voice/linkmon.py)가 이미 100Hz
> 샘플링 인프라를 갖고 있으니 한 줄 추가다. PID 튜닝을 **재플래시 없이 브라우저에서**
> 하게 되는데, 이건 `F`/`P`/`R`로 이미 검증된 방식이다.

## 8. 캘리브레이션 — **보드에 속한 데이터**다

보드가 바뀌면 duty↔속도 곡선도, 문턱도, 극성도 바뀐다. 그러니 캘리브레이션은
코드가 아니라 **그 보드의 소유물**이다.

### 어디에 사는가

| 위치 | 역할 |
|---|---|
| **보드의 비휘발성 메모리** (Flash/EEPROM) | **정본.** 보드를 옮기면 따라온다 |
| 젯슨 `~/calib/<board_id>.json` | 미러 사본. 보드가 죽었을 때 새 보드에 복원용 |
| `config.py` | **공장 초기값만.** 런타임 값은 여기 없다 |

`cap.id`로 파일을 고른다. 즉 **보드를 두 개 굴려도 섞이지 않는다.**

### 무엇이 들어가는가

| 항목 | 명령 | 비고 |
|---|---|---|
| 바퀴 극성 ±1 ×4 | `L` | |
| 엔코더 CPR, 바퀴 지름 | `N` | 개루프 보드는 없음 |
| 기하 lx, ly | `M` | 차체 속도 ↔ 바퀴 속도 변환 |
| 바퀴별 Kv, Ks, Kp, Ki | `G` | **Ks가 정지마찰 보상** — §10 참고 |
| 슬루, duty 상한, PWM 주파수 | `R`, `P`, `F` | |
| 전압 분압비, 저전압 문턱 | `B` | |

### 절차

1. `T`로 바퀴 배선·극성 확정 → `L`
2. 엔코더 있으면 `N`, 기하 `M`
3. **`Ks` 측정** — duty를 올려가며 바퀴가 실제로 돌기 시작하는 값을 축별로 찾는다
4. **`Kv` 측정** — 몇 개 duty에서 정상 속도를 재 기울기를 얻는다
5. `Kp`/`Ki`는 작게 시작해 `st` 비트5(포화)를 보며 올린다
6. `E`로 저장 → `cap.calib=1`이 되는지 확인

> ⚠ **캘리브레이션을 다시 하면 저장된 프리셋·튜닝의 뜻이 바뀐다.** 팔에서 이미
> 겪은 일이다([`arm.py`](../src/tomato_picker/hardware/arm.py)의 경고). 베이스도
> 같으므로, 재캘리브레이션 뒤에는 라인 튜닝을 다시 확인한다.

## 9. 데드맨 계층 — 시한은 계약이다

각 층은 **위층이 통째로 사라져도** 안전측으로 떨어진다. 구현이 바뀌어도 이 표는
바뀌지 않는다.

| 층 | 감시 주체 | 시한 | 동작 | 위가 죽으면 |
|---|---|---|---|---|
| 1 | **보드 하드 데드맨** | 1000ms | 즉시 0 | 젯슨이 통째로 죽어도 정지 |
| 2 | **보드 소프트 데드맨** | 300ms | 슬루로 감속 | 링크가 끊겨도 부드럽게 |
| 3 | **젯슨 재전송 스레드** | 20ms 송신 / `STALE_SEC` 0.5s | 목표를 0으로 | 상위 로직이 밀려도 유지 |
| 4 | **지령 TTL**(조정자) | 200~500ms | 다음 우선순위로 강등 | 행위 프로세스가 죽으면 정지 |
| 5 | **하드웨어 비상정지** | 즉시 | 출력단 차단(`X 1`) | 펌웨어가 물려도 정지 |

> ⚠ **5층이 왜 필요한가.** 현행 구조에서 워치독이 보드를 리셋해도 **PCA9685는
> 별개 칩이라 리셋되지 않는다** — 부트로더 ~2초 동안 마지막 duty가 계속 출력된다.
> 즉 지금 유일한 비상정지가 "2초 뒤에 듣는 리셋"이다. 새 보드는 PWM을 MCU가 직접
> 만들므로 리셋이 곧 정지가 되고, `estop_hw=1`이면 그보다도 빠르다.

## 10. 제어 규약 — 보드가 지켜야 할 것

### 10.1 속도 제어 구조

```
duty = Kv·v_target  +  Ks·sign(v_target)  +  PID(v_target − v_meas)
       ^ 속도 이득      ^ 정지마찰 보상        ^ 잔차만
```

- **feedforward를 반드시 넣는다.** `Ks`가 곧 지금의 "문턱 90"이다. PID만으로 문턱을
  넘기려 하면 적분이 쌓일 때까지 굼뜨고 그 다음엔 오버슛한다.
- **적분 와인드업 방지 필수.** 출력이 포화되면 적분을 멈춘다(clamping). 바퀴가 안
  도는 동안 적분이 쌓이면 문턱을 넘는 순간 튀어나간다 — **이 프로젝트의 "1번 병"이
  PID에서는 와인드업으로 모습을 바꿔 나타난다.**
- **D항은 기본 0.** 저해상도 엔코더에서 미분은 노이즈만 키운다. PI + feedforward로
  시작한다.
- **저속 속도 추정은 M/T 혼합.** 고정 주기 카운트 차분(M법)만 쓰면 저속에서 심하게
  양자화된다. 지점 정렬처럼 아주 느린 국면에서 결정적이다.
- **제어 주기는 타이머 인터럽트로 고정.** `loop()` 안에서 `millis()` 비교로 하면
  시리얼·I2C가 끼어들어 지터가 생긴다 — 젯슨을 떠난 이유를 보드에서 재현하면 안 된다.

### 10.2 정지와 모드 전환

- `S`/`X`/데드맨은 **PID를 우회**한다. 적분을 리셋하고 출력을 직접 0으로.
- 목표 0은 "능동 제동"이 아니라 "슬루로 감속"이다. 급제동이 필요하면 `S`.

### 10.3 명령 하나마다 워치독 예산

버퍼에 쌓인 명령은 한 loop 패스에서 전부 처리된다. 현행 펌웨어가 이미
`wdt_reset()`을 명령마다 넣는다 — **계약으로 승격한다.** 이걸 어기면
`재부팅 → 설정 재적용 → 다시 재부팅`의 자기증폭 고리가 생긴다(2026-08-11 실측).

## 11. 젯슨 쪽 구조

### 11.1 인터페이스

```python
class MobileBase(Protocol):
    def set_velocity(self, vx_mms: int, vy_mms: int, w_mdegs: int) -> None: ...
    def stop(self) -> None: ...
    def estop(self, on: bool) -> None: ...
    def caps(self) -> Caps: ...           # cap 파싱 결과 (없으면 레거시 프로파일)
    def telemetry(self) -> Telemetry: ... # tgt/act/vin/amp/st/링크품질
```

duty 계열(`V`/`P`/`F`/`T`)은 **`LegacyDutyControl`이라는 선택적 인터페이스로 격리**한다.
`caps().units == 0`인 보드에서만, 그리고 진단 화면에서만 쓴다. 주행 로직은 이 인터페이스를
**알지 못한다.**

### 11.2 구현들

| 구현 | 설명 | 계약 테스트 |
|---|---|---|
| `MockBase` | 아무것도 안 함 | 필수 항목만 |
| `SimBase` | 1차 지연 + 정지마찰 물리 모델 | **전부** |
| `UnoAdapterBase` | 현행 Uno + 캘리브레이션 테이블로 mm/s→duty | 개루프 항목 |
| `Stm32Base` | 새 보드, 폐루프 | **전부** |

> **`SimBase`가 왜 필수인가.** 추상화가 진짜인지는 **구현이 둘 이상일 때만** 알 수
> 있다. 하나뿐인 추상화는 늘 새고 있고, 지금
> [`base.py`](../src/tomato_picker/hardware/base.py)가 정확히 그 상태다(추상화는
> 있는데 duty가 그대로 뚫고 나온다). 그리고 `SimBase`가 생기면 **하드웨어 없이
> [`line_drive.py`](../src/tomato_picker/hardware/line_drive.py) FSM을 테스트**할 수
> 있다 — 이 프로젝트에 테스트가 0인 문제가 같이 풀린다.

### 11.3 대시보드

- 슬라이더 범위를 **`cap.vmax`/`wmax`에서 만든다.** 코드에 상수로 박지 않는다.
- `cap.closed_loop=0` → PID 패널 숨김 + "개루프" 배지
- `cap.calib=0` → **주행 버튼을 잠그고** 캘리브레이션 화면으로 유도
- `/diag`에 `tgt` vs `act` 겹쳐 그리기, `vin` 파형 겹쳐 그리기

## 12. 계약 테스트 — "교체 가능"의 조작적 정의

같은 스위트를 **모든 구현**에 돌린다. 통과하면 갈아끼울 수 있고, 아니면 못 한다.

**프로토콜**
- [ ] 잘못된 체크섬은 실행되지 않고 `nak crc`
- [ ] strict 전환 후 무체크섬 `C`/`V`는 `nak nocrc`
- [ ] 모르는 명령은 `nak unsupported`이며 **조용히 무시하지 않는다**
- [ ] `cap`이 부팅 직후 1회, `Q`마다 발행된다
- [ ] `proto` 불일치 시 젯슨이 연결을 거부하고 사용자에게 알린다

**단위**
- [ ] `C 350 0 0` 후 정상 상태에서 `act.vx`가 350±허용오차 (폐루프 구현만)
- [ ] `C 0 0 90000` 후 실제 회전이 90°/s±허용오차
- [ ] 부호 규약: +vx=전진, +vy=(§14에서 결정), +w=반시계

**안전**
- [ ] 지령을 끊으면 **300ms 내 감속 시작, 1000ms 내 완전 정지**
- [ ] `X 1` 중 `C`는 `nak estop`이고 출력이 0
- [ ] `S`는 슬루를 무시하고 즉시 0
- [ ] `calib=0`인 보드에 `C`를 보내면 `nak nocalib` (조용히 아무 일도 안 하지 않는다)

**계측**
- [ ] `hb`가 1초 주기로 오고 `ms`가 단조증가
- [ ] 보드를 리셋하면 젯슨이 **재부팅을 감지**하고 설정을 다시 밀어넣는다
- [ ] `st` 비트가 실제 상태와 일치 (데드맨·포화·저전압)

**교체**
- [ ] `SimBase`와 `Stm32Base`가 **같은 주행 시나리오에서 같은 FSM 판정**을 낸다

## 13. 마이그레이션 — 각 단계가 혼자서도 가치가 있다

| 단계 | 내용 | 하드웨어 | 데모 리스크 |
|---|---|---|---|
| **0** | 이 문서 확정 (§14 결정 항목 닫기) | 없음 | 0 |
| **1** | 젯슨을 계약에 맞춰 재배치 + `UnoAdapterBase` | 없음 | 0 |
| **2** | `SimBase` + 계약 테스트 + CI | 없음 | 0 |
| **3** | 접지 별 결선 + USB 아이솔레이터 | 배선 | 낮음 |
| **4** | STM32 구현 (PID·엔코더·20kHz PWM·`cap`) | 보드 | 병행 개발 |
| **5** | 전환 — 설정 플래그 하나 | 꽂기 | 되돌리기 가능 |

**호환성 규칙**

- 1단계 이후에도 **현행 Uno 펌웨어는 그대로 동작한다**(§6 레거시 프로파일).
- 4단계 중에도 `V`(duty) 경로는 살아 있다 — 캘리브레이션 전이나 진단 시 폴백.
- 5단계는 **되돌릴 수 있어야 한다.** 보드를 바꿔 끼우면 `cap`이 달라지고 젯슨이
  알아서 적응한다.

## 14. 결정이 필요한 항목

구현을 시작하기 전에 닫을 것.

1. **부호 규약** — +vy가 좌인가 우인가. 현행 [`config.py`](../src/tomato_picker/config.py)
   실측 매핑(`A=FR B=FL C=RR D=RL`, `POL={-1,1,-1,1}`)과
   [`line_drive.py`](../src/tomato_picker/hardware/line_drive.py)의 게걸음 부호를
   맞춰 **한 번만** 정한다. 지금은 런타임 `flip` 토글이 있는데, 그 토글의 존재
   자체가 규약 부재의 증거다.
2. **`wmax` 기준점** — 회전 속도를 차체 중심 기준으로 정의할 것. 회전 중심이
   카메라에서 벗어나 있다는 실측(1° ≈ 진행축 17px)은 젯슨 쪽 기하 문제로 분리한다.
3. **비휘발성 저장 매체** — STM32 Flash 마지막 페이지 vs 외부 EEPROM. 쓰기 수명과
   전원 차단 중 쓰기 안전성.
4. **`estop_hw` 구현 방식** — 드라이버 nSLEEP 차단 / PWM 타이머 강제 정지 /
   (현행 보드 개조 시) PCA9685 `OE` 핀.
5. **엔코더 전압** — 5V 엔코더를 3.3V MCU에 물릴 때 5V tolerant 핀 확인 또는
   3.3V로 급전.
6. **`C`의 최소 유효 크기** — 문턱 아래 지령을 보드가 거절할 것인가, feedforward로
   흡수할 것인가. 폐루프면 후자가 맞지만, 극저속 헌팅 한계를 실측해서 정한다.
