## 2. 다른 PC에서 시작하는 법

```bash
git clone <origin> && cd tomato-picker
git checkout feat/ros2-arm-estimation
```

그 다음 브라우저로 **http://192.168.0.6:8090/** 를 연다. 끝이다.
팔 조작·잡기·집게·자세는 전부 그 화면에서 된다. 터미널이 꼭 필요한 일은 없다.

젯슨의 코드를 고쳤으면 올려야 한다(git clone이 아니라 **scp**로 배포한다):

```bash
tr -d '\r' < ros2/tools/stem_grasp.py > /tmp/x.py
scp /tmp/x.py server@192.168.0.6:~/tomato-picker/ros2/tools/stem_grasp.py
# click_server.py 를 고쳤으면
ssh server@192.168.0.6 'sudo systemctl restart click-server'
```

⚠ **CR 제거(`tr -d '\r'`)를 빼먹지 말 것** — 윈도우에서 그냥 scp 하면 젯슨에서 깨진다.

## 3. 조작대 API — 사람과 에이전트가 같은 문을 쓴다

이 세션의 후반부터 **모든 조작을 이 API로만** 내렸다. 화면의 버튼, `curl`,
에이전트가 전부 같은 경로다. 재현이 안 되는 조작을 남기지 않기 위해서다.

```
GET  /state                 상태 (프레임 나이, 표적, 십자, 도는 일)
GET  /log?since=N           로그 이어받기
GET  /frame.jpg             손목 화면
POST /click  {u,v,mode}     mode=target(줄기) | grip(십자 위치)
POST /clear                 표적 지움
POST /run    {job,args}     아래 표
POST /stop                  도는 일 끊기
```

| job | args | 하는 일 |
|---|---|---|
| `park` | — | 대기 자세 `60,65,0,-100,6`(도) |
| `stage` | `target:"60,65,0,-100,6"` | 그 관절 자세로 |
| `pose` | — | 지금 자세·TCP 읽기 |
| `jog` | `dx dy dz along horiz pitch piece free_pitch` | 손끝을 mm로 옮긴다 |
| `grip` | `value:0~100` | 집게 (78=열림, 4=닫힘) |
| `grasp` | `steps adv max_turn gain tol stop_z rejacobian no_close dry` | 찍은 줄기로 가서 문다 |

```bash
curl -s -XPOST 192.168.0.6:8090/run -H 'Content-Type: application/json' \
     -d '{"job":"grasp","args":{"steps":18,"adv":8,"tol":28,"stop_z":88}}'
```

⚠ **한 번에 하나만 돈다.** 팔 포트(`/dev/ttyACM0`)를 한 프로세스만 열 수 있어서,
도는 중에 새 일을 넣으면 **409**로 거절하고 이유를 돌려준다.

## 4. 오늘 실측으로 확정한 값 (다시 재지 말 것)

| 값 | 실측 | 어떻게 쟀나 |
|---|---|---|

## 5. 오늘 고친 병 (같은 함정에 다시 빠지지 않게)

1. **중력 처짐이 걸음을 잡아먹는다.** 명령보다 2~3° 아래 서기 때문에, 걸음이
   그보다 작으면 **순효과가 음수**다 — 70mm 올리랬더니 15mm 내려갔다.
   → 모자란 만큼 명령에 더해 다시 보내는 **적분 보정**(`press_to`/`go`). 지금 70에 67.7mm.

2. **병진은 자세를 묶어야 한다.** 4관절 최소노름 병진은 남는 자유도로 카메라를
   확 돌린다 — 12mm 나아가랬는데 손목 카메라가 천장을 봤고, 그게 "닿았다" 오판까지
   만들었다. → 피치 고정 구속 한 줄(`step_keep`, `move_base`).

3. **한계는 거부가 아니라 처리.** 축 하나가 한계라고 걸음을 통째로 버리면 14걸음
   내리 0mm다. → 겨냥은 **잘라서라도** 가고(`clamp`), 전진은 **걸음을 줄인다**.
   ⚠ 단 전진에서 자르면 병진이 회전이 된다 — 그래서 전진만 다르게 처리한다.

4. **곧게 편 팔은 특이점**이다(elbow≈0°). 접근축으로 10mm 가는 데 84°가 필요했다.
   굽힌(elbow-down) 자세면 3.2°면 된다.

5. **깊이 판독이 튄다.** 가는 줄기는 한 프레임이 배경을 물면 63mm가 355mm로 읽힌다.
   → 3장 중앙값 + "**늘어난 건 접촉이 아니다**" + 2회 연속 정체만 접촉.

6. **밀지 말고 문다.** 손끝 거리를 아는데 접촉을 기다릴 이유가 없다.
   → `--stop-z 88`: 겨눈 자리가 그 거리에 들면 그 자리에서 닫는다.
   이 규칙이 없어서 **열매를 세 번 떨어뜨렸다.**

7. **추적이 미끄러지면 야코비안 부호가 뒤집힌다.** 깊이창 무게중심으로 따라가니
   줄기를 따라 미끄러져 겨냥이 152→95→143→101px로 진동했다.
   → **템플릿 정합(배율 3단)** 으로 교체. 지금 정합도 1.00.

8. **화면에 빨간 것이 여럿이다** — 매달린 열매 둘, 책상에 떨어진 열매, 선반의
   **주황 안전조끼**. 서보가 화소오차 8까지 말끔히 수렴했는데 겨눈 것이 조끼였고
   (집게는 바닥에 코를 박고 있었다), 다음엔 책상 열매였다(팔이 자기 몸통에 닿았다).
   → 둥글기 조건으로 조끼를 거르고, **어느 열매인지는 사람이 클릭**한다.

9. **손목 화면 상하 반전 여부로 두 번 헤맸다.** 결론: **뒤집히지 않았다.**
   집게 손가락(화면 아래)과 열매(화면 위)가 한 프레임에 같이 찍힌 사진으로 확정했다.
   "링이 열매 아래로 보인다"고 판단했던 건 *아래쪽* 링이었다.

## 6. 아직 안 된 것 · 다음 수

**남은 것은 마지막 40mm다.** 겨냥이 20px 안으로 들어오고 깊이가 110~130mm까지
오는데, 거기서 88mm까지 좁히는 전진이 관절 한계에 막히거나 깊이 잡음에 흔들린다.

시도해 볼 순서:

1. **굽힌 자세에서 시작한다.** 대기 자세(`60,65,0,-100,6`)는 팔이 곧게 펴진
   특이점이라 전진이 안 된다. 역기구학으로 찾아 둔 굽힘 자세 예:
   `stage {"target":"59.6,35.7,39.8,-100.5,0.0"}` (r250·z250, 10mm에 3.2°).
   ⚠ 이 자세는 열매에 아주 가깝다(줄기가 82mm로 읽혔다). 열매 위치가 바뀌면 다시 찾아야 한다.
2. **전진 방향을 실측으로 고른다.** `stem_grasp.py`에 이미 들어 있다 — 접근축이
   막히면 `접근/수평/위/아래/수평뒤/옆` 여섯 방향을 12mm씩 찔러 보고 **깊이가
   가장 많이 주는 쪽**으로 간다. 로그에 그 표가 찍힌다.
3. 그래도 안 되면 **손목 각도(`jog pitch`)를 바꿔** 접근 방향 자체를 돌린다.

**해도 소용없다고 확인된 것** (다시 하지 말 것):
- 전역 손-눈 보정: 잔차 44mm에서 안 내려갔다. 회전·링크길이·영점·측면오프셋·
  화면위치 전부 배제했는데 원인을 못 찾았다.
- 국소 손-눈 회전 실측(`cam_frame.py`): 깊이 잡음이 걸음과 비슷한 크기라
  특이값이 1.84/0.91로 나오고 잔차 20mm였다. **회전이 안 나온다.**
- **객체인식으로 줄기 찾기**: 젯슨의 `yolov8s-worldv2.pt`(개방어휘)로
  "tomato stem", "green plant stem" → **0개**. 열매는 PC 화면에서 conf 0.16으로
  잡히지만 손목 근접 화면에서는 0개다(torch가 **CPU판**, 추론 1.6초/장).
  `ultralytics`는 설치해 뒀으니 CUDA torch를 올리면 다시 볼 만하다.

## 8. 이어받는 사람에게 — 순서

1. 방에 **불을 켠다**. 컬러가 어두우면 클릭도 추적도 안 된다(01:20에 이걸로 멈췄다).
2. http://192.168.0.6:8090/ → **대기 자세**.
3. **① 줄기 찍기** → 화면에서 줄기 클릭. ⚠ **자세가 바뀌면 다시 찍어야 한다** —
   클릭은 그 프레임의 화소 자리라서, 팔이 움직이면 그 화소는 다른 것을 가리킨다.
4. 필요하면 **② 십자 옮기기**로 손가락 사이를 다시 찍는다.
5. **잡으러 간다.** 가는 중에 엉뚱한 걸 물면 **다시 클릭만** 하면 그 즉시 표적이 바뀐다
   (매 걸음 파일을 다시 읽는다).
6. 이상하면 **지금 하는 일 끊기** → **대기 자세**.
