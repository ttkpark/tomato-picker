# 재플래시 복구 핸드오프 — 2026-07-29

젯슨이 **전원 브라운아웃 누적으로 NVMe 부팅 구조가 손상 → 벽돌화**됐고,
Windows SDK Manager로 **재플래시** 후 프로젝트를 처음부터 재설치했다.
다음 작업자(사람/에이전트)가 헷갈리지 않도록 현재 상태를 남긴다.

## 지금 젯슨 상태 (실기)

- **OS 새로 깔림**: Ubuntu 24.04.4 + L4T R39 / **JetPack 7**, Python 3.12. (이전은 구버전)
- 접속: `ssh server@192.168.0.8` (SSH키 재등록 완료, passwordless sudo 복구). **IP는 DHCP라 바뀔 수 있음** → 공유기 고정IP 예약 권장.
- **전원 문제 해결됨**: 젯슨을 모터/베이스와 **독립 전원으로 분리** → 베이스 주행해도 리셋 안 남(실측 검증). 이게 벽돌화 근본원인이었다.

## 지금 동작하는 것 ✅

- **음성 서비스 `tomato-voice`** 부팅 자동실행(systemd, enable+active). 대시보드 `http://<젯슨IP>:8090`.
- **베이스(바퀴) = 실제 동작**: "앞으로 가"/"전진" → 1.5초 전진, "토마토" → 전진1초→(팔 하는척)→후진1초.
- **음성 STT**: faster-whisper `base`, **CPU**(int8). 환각 게이트/정규화 튜닝 적용됨.

## ⚠️ 상태 불일치 — 다음 작업자 주의

- **repo `config.py`는 `USE_REAL_ARM = True`** 지만, **젯슨 실기는 `USE_REAL_ARM = False`(팔=MockArm "하는 척")** 로 돌고 있다.
  - 이유: **`arm_presets.json`이 재플래시로 날아갔고 백업이 없어** 팔 프리셋을 아직 재교시 못 했다. presets 없이 `USE_REAL_ARM=True`면 서비스가 크래시한다.
  - **repo를 젯슨에 그대로 재배포하면 팔이 True가 되어 깨진다** — 재배포 시 젯슨에서 `USE_REAL_ARM=False` 유지하거나 presets부터 만들 것.

## 다음 작업 (팔 실제 복원)

1. 팔(팔로워) 연결 확인: `/dev/ttyACM0`, 모터 6개 스캔 OK, **캘리브레이션은 이미 완료**
   (`~/.cache/huggingface/lerobot/calibration/robots/so_follower/tomato_follower.json`).
2. **`arm_presets.json` 재교시** (백업 없음 — 수동 조그 또는 리더암 미러링으로 프리셋 1→2→3→4 저장, `~/arm_presets.json`).
3. 젯슨 config에서 `USE_REAL_ARM = True`로 되돌리고 `sudo systemctl restart tomato-voice`.

## 재설치 시 알아야 할 젯슨 환경 메모

- venv = `~/lerobot/.venv`. 설치: `lerobot==0.5.1`(PyPI에 0.5.2 없음), `feetech-servo-sdk`, `faster-whisper`,
  `pyserial`, `python-dotenv`, `numpy`. **torch 2.10.0+cpu**(이 데모는 전부 CPU, CUDA 불필요).
- **CH340 베이스 드라이버(ch341)가 JetPack7 커널에 없음** → out-of-tree 빌드해 설치함
  (`~/ch341build`, `/lib/modules/$(uname -r)/kernel/drivers/usb/serial/`에 설치 + depmod). 재플래시 시 재빌드 필요.
- `server`를 `dialout,audio,input,video` 그룹에 추가함.
- 장치: `/dev/ttyUSB0`=베이스(CH340), `/dev/ttyACM0`=팔(팔로워).
