# 대시보드 수동 조작 — 리더암·프리셋 10슬롯·높이 보간

접속: `http://<젯슨IP>:8090/control` (대시보드 상단 "🎮 수동 조작" 링크)

터미널/SSH 없이 브라우저만으로 **자세를 만들고 저장하고 섞어 쓰는** 화면.
예전에는 `tools/mirror_toggle.py`를 SSH로 띄워야 했다.

## 0. 모터 튜닝 — 소음 ↔ 속도는 맞바꾸는 관계다

**PCA9685는 1526Hz가 물리적 상한**이라 PWM을 가청대역(~20kHz) 위로 못 올린다.
즉 "무음"은 선택지가 아니고 **어떤 소리를 고를지**의 문제다. 게다가 주파수를 올리면
드라이버 스위칭 손실이 커져 같은 지령에서도 **속도가 떨어진다**(2026-08-06 실측).

| 주파수 | 소리 | 힘 |
|---|---|---|
| 50Hz | "우우웅" 저역 울림 | 가장 셈 (벤더 기본값) |
| 400Hz | 중저역 웅 | 중간 |
| **700Hz** | 웅~찡 경계 | 중간 **(현재 기본값)** |
| 1526Hz | "찌잉" 고역 휘파람 | 가장 약함 (상한) |

속도 보상은 **듀티 상한**으로 한다. 벤더 코드도 `MAX_VALUE = 2000`(4095 중 49%)만 써서
**2배 헤드룸이 남아 있다** — 주파수를 올려 잃은 만큼 여기를 키우면 같은 속도를 더 높은
주파수로 낼 수 있다. 현재 기본값은 `2600`.

`/control`의 **모터 튜닝** 패널에서 재플래시 없이 즉시 바꿔가며 귀로 찾으면 된다.
프리셋 버튼(50 / 400 / 700 / 1100 / 1526Hz)은 주파수와 듀티를 짝지어 바꾼다.

- 패널의 **`← 보드 확인: ok F 700 | ok P 2600 | ok R 6 12`** 가 뜨면 값이 실제로 먹은 것이다.
  이게 없으면 요청만 갔고 보드는 예전 값 그대로다.
- 마음에 드는 값은 `config.py`의 `BASE_PWM_HZ` / `BASE_MAX_PWM` / `BASE_SLEW_ACCEL`에 적어두면
  다음 부팅부터 기본값이 된다(연결될 때마다 자동으로 밀어넣는다).
- ⚠ 듀티를 키우면 전류도 커진다. **젯슨이 리셋되면 듀티 상한부터 내릴 것**
  ([[battery-power-system]]). 가속(슬루)을 낮추면 최고속도는 그대로 두고 기동 피크만 깎인다.

> **함정**: 포트를 여는 순간 커널이 DTR을 토글해 **Uno가 리셋된다**(dtr=False로 열어도).
> 그 직후 ~2초는 부트로더 구간이라 이때 보낸 F/P/R은 통째로 먹힌다. 그래서 MotorLink는
> **첫 하트비트를 받은 뒤에** 튜닝을 밀어넣는다. 직접 시리얼로 설정을 넣을 때도 같은
> 2초를 기다려야 한다.

## 1. 자세 만들기 — 두 가지 길

| 방식 | 준비물 | 순서 |
|---|---|---|
| **리더암 미러링** | SO-101 Leader USB 연결 | ① `리더암 연결` ② `미러링 시작` ③ 리더를 손으로 원하는 자세로 ④ 팔로워가 따라옴 |
| **힘 빼기** | 없음(팔로워만) | ① `힘 빼기`(또는 <kbd>R</kbd>) ② 팔로워를 손으로 직접 잡아 자세를 만듦 |

- 리더 포트는 **팔로워가 쓰는 포트를 뺀** ttyACM 후보에서 고른다(드롭다운). 자동선택도 됨 —
  리더/팔로워가 둘 다 CH343이라 번호가 서로 바뀔 수 있어 하드코딩하지 않는다.
- `미러링 중지`를 눌러도 팔로워는 **토크를 유지**한다. 여기서 힘을 빼면 방금 만든 자세가
  중력에 무너져 저장할 게 없어지기 때문.

## 2. 프리셋 슬롯 0~19

화면 상단의 **모드**가 슬롯 버튼의 의미를 정한다(`mirror_toggle.py`의 조작감 계승).

- `▶ 재생` 모드 — 슬롯을 누르면 그 자세로 이동
- `● 등록(저장)` 모드 — 슬롯을 누르면 **지금 팔 자세**를 그 슬롯에 덮어씀(확인창 있음)

키보드 <kbd>0</kbd>~<kbd>9</kbd>도 현재 모드로 동작하고, **<kbd>Shift</kbd>+<kbd>0</kbd>~<kbd>9</kbd>가
슬롯 10~19**다(`e.key`로는 Shift+1이 `!`로 와서 못 가르므로 `e.code`로 읽는다).
슬롯마다 `이름`(접근/집기 등), `앵커`(아래 참고), `비우기`를 달 수 있다.

슬롯 개수는 `hardware/presets.py`의 `SLOT_COUNT` 하나로 정한다 — 대시보드 격자는
`auto-fill`이고 시퀀스 파서는 `\d+`라 두 자리 슬롯도 그대로 먹으므로, 그 상수만 바꾸면
저장소·화면·게임패드가 전부 따라온다.

저장 위치는 `~/arm_presets.json` — 게임패드 드라이버(`controller_drive.py`)가 읽는 파일과
같다. 형식은 **옛 파일과 호환**되며(숫자 키 = 자세), 이름·앵커 메타데이터만 `"__meta__"`
키에 따로 들어간다. 저장은 임시파일 → `os.replace` 원자적 교체라, 데모 중 전원이 나가도
프리셋 파일이 깨지지 않는다.

## 3. 높이 보간 — 프리셋 섞어 쓰기

**질문이었던 부분**: 10슬롯 자유저장과 "상/중/하 3단" 중 무엇이 맞나 →
**둘 다 쓴다.** 슬롯 번호 순서를 높이축으로 가정하면(4와 6 사이=5) 시퀀스용 프리셋과
높이용 프리셋이 같은 번호공간을 나눠 쓰게 돼 '집기' 자세와 '들기' 자세가 섞이는 사고가
난다. 그래서 **높이축에는 명시적으로 태그한 슬롯만 참여**시킨다.

슬롯의 `앵커` 버튼 → 라벨(상/중/하)과 **기준 높이 y**(카메라 화면 세로 픽셀, 위=0)를 지정.

```
슬롯4 = 상 (y=250)      토마토 y=330
슬롯6 = 중 (y=420)   →  상:중 = 53% : 47% 로 관절값 선형보간 → 재생
슬롯8 = 하 (y=600)
```

- `이 높이로 이동` — 슬라이더로 정한 y
- `🍅 감지된 토마토 높이로 이동` — 비전이 본 **가장 아래 공중 토마토**의 y를 그대로 사용
  (아래쪽부터 따는 게 수확 순서로 자연스럽고, 위 열매를 건드려 떨어뜨리지 않는다)
- 앵커 범위 **바깥은 외삽하지 않고** 끝 앵커로 고정한다 — 외삽은 팔이 사거리 밖으로
  나가려 드는 위험한 동작이 되기 쉽다.
- 결과 설명(`'상'(슬롯 4) : '중'(슬롯 6) = 53% : 47%`)이 화면과 대시보드 로그에 남는다.

**보간이 물리적으로 말이 되는 이유**: 앵커들은 같은 접근 방향에서 팔 높이만 다른 자세다.
그런 자세들 사이의 관절공간 선형보간은 실제로도 그 사이 높이를 가리킨다. 임의의 두 자세를
섞으면(예: '집기'와 '놓기') 중간이 엉뚱한 곳을 향하므로, 앵커만 섞는 규칙이 안전장치다.

## 4. 시퀀스

`1,2,3,4`처럼 쉼표로 적어 `순서대로 재생`. 수확 전체 시퀀스(접근→집기→들기→놓기)는
`전체 시퀀스(1→4)` 버튼이 그대로 재생한다([[tomato-pick-sequence]]).

## 5. 링크 상태 줄

맨 위 카드가 모터보드 링크 품질을 실시간으로 보여준다.

```
● 바퀴 링크 정상 · /dev/serial/by-id/...USB_Serial-if00 · hb 0.4s 전 · 수신 12043
```

- `hb N초 전` — 펌웨어 하트비트. 3초 넘게 안 오면 "끊김"으로 뜬다.
- `⚠ 깨진프레임 N` — 체크섬 불일치로 **거부한** 지령 수. 늘어나면 USB 케이블/전원 문제다
  (이 숫자가 0이 아니면 예전 같으면 그 지령이 그냥 실행됐다는 뜻).
- `Device or resource busy` — `controller-drive`(게임패드) 서비스가 포트를 이미 잡았다.
  둘 중 하나만 켤 것: `sudo systemctl stop controller-drive`
