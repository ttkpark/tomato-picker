# 보정 종이 세 장 — 각각 무엇을 보정하나 (2026-11-09)

인쇄물 = [`docs/aruco/`](aruco/) (A4 **실제 크기 100%** 인쇄, 아래 100mm 눈금자로 배율 확인. 다시 만들기 = `python tools/aruco_print.py`).
2026-11-09 사용자가 셋 다 인쇄해 작은 방 벽(둘)·바닥(하나)에 붙였다.

## 한 그림 — 좌표가 거쳐 가는 사슬

손목 카메라가 본 점 하나가 지도 위 점이 되기까지 변환 넷을 거친다. 셋은 이미 알거나 재고, **둘이 틀려 있거나 비어 있어서** 종이로 푼다.

```
 D405가 본 점(카메라 좌표)
   │  ① 손-눈 보정  T_tool_cam          ← 벽 보드(ChArUco / 4점)     [도구 있음, 재채집 대기]
   ▼
 손끝(도구 좌표)
   │  ② 순기구학 FK(관절값)             ← 링크 길이·영점(이미 잰 값, kinematics.py)
   ▼
 팔 바닥(회전판 위)
   │  ③ 회전판 → 차체  wrist_to_body    ← 같은 벽 보드, 회전판만 돌려서 [도구 없음]
   ▼
 차체(로봇 중심)
   │  ④ 차체 → 지도  pose(x, y, θ)       ← 바닥 HOME 마커(절대 기준)   [도구 없음]
   ▼
 지도(방) 좌표
```

틀린 고리가 하나라도 있으면 그 아래가 전부 틀린다. 그래서 ①부터 푼다.

## ① 손-눈 보정 — 벽 보드 (`charuco_wall.pdf` 권장, `dots_wall.pdf` 예비)

**무엇을**: 손목 D405가 **손끝에 대해 어디에, 어느 방향으로** 붙어 있는가. 회전 3개 + 평행이동 3개짜리 강체 변환 `T_tool_cam` 하나.
자로 재지 않는다 — 브래킷·렌즈 중심을 자로 맞출 수 없고, 9/4에 브래킷이 1°/2mm 헐거웠던 것처럼 실물이 도면과 다르다.

**어떻게**: 벽의 보드는 안 움직인다. 팔을 여러 자세로 바꿔 보면 자세마다 식이 하나씩 생긴다.
```
보드 위치(팔 바닥, 고정) = FK(관절값) · T_tool_cam · (카메라가 본 보드 점)
```
아는 것 = FK·카메라 점, 모르는 것 = `T_tool_cam`·보드 위치 → 최소자승 한 번([`handeye.py`](../src/tomato_picker/hardware/handeye.py) `solve_on_arm`, 미지수 15).

- **사진 → 점**: ChArUco는 안쪽 모서리 최대 24개를 찾아 칸 크기(35mm)로 PnP — **깊이 없이** 보드 3D 자세가 나온다(재투영 > 2px면 버림, [`target_check.py`](../ros2/tools/target_check.py) `charuco_points`). 4점 종이는 점 4개 + D405 깊이, 점 사이 거리(100×174.5mm)로 묶는다. 시뮬에서 ChArUco ≈4mm, 4점 5~10mm.
- **채집** [`handeye_collect.py`](../ros2/tools/handeye_collect.py): 접힌 시작 자세에서 4축(pan·wrist_flex = 회전, lift·elbow = 카메라를 **옮김**)으로 흔들어 8장 이상. 회전만 흔들면 평행이동이 안 풀린다(8/31 −575mm). 끝에 시작 자세로 돌아가 **표류 검사**(5mm 넘으면 브래킷이 밀린 것).
- **풀이** [`handeye_resolve.py`](../ros2/tools/handeye_resolve.py)(PC에서도 돎): **거울 유무 × roll 부호 ±1, 4조합**을 다 푼다 — 9/4 "평행이동 3~5배"의 원인이 FK와 실물이 거울상이었던 것(11/08 옛 표본 재풀이: 거울+roll+1 10.3mm·|t| 107mm). 합격 = 잔차 ≤ 15mm · `|t|` 60~160mm · 한 장씩 빼도 안 흔들림. 통과하면 `~/arm_eye.json`에 **어느 식으로 풀었는지(`frame`)와 함께** 저장.

**보정되면 되는 것**: D405가 본 3D 점(줄기·토마토)을 **팔 좌표 mm**로 옮긴다 → 화소 시각서보 대신 좌표로 잡기(ROS 2 계통 `ros.2`의 전제), 조작대 3D 미리보기, `space_map` 손목 담기.

**절차**(사람 입회): 로봇을 Astra가 보드 벽을 정면으로, 손목 카메라↔보드 30~40cm에 놓는다 → `sudo systemctl stop click-server` →
`~/lerobot/.venv/bin/python ~/tomato-picker/ros2/tools/handeye_collect.py --target charuco --save` (`--home here` 금지) → `sudo systemctl start click-server`.

## ③ 회전판 → 차체 (`wrist_to_body`) — 같은 벽 보드를 다시 쓴다

**무엇을**: 팔 전체가 얹힌 **회전판(서보 ID 7)의 축이 차체 어디에 있고, 회전판 몇 도가 차체 정면인가.**
지금 코드([`space_map.py`](../ros2/tools/space_map.py) `wrist_to_body`)는 "회전판 축 = 차체 앞 `arm_x`, 회전판 각 그대로 차체 각"을 가정한다.
그런데 10/24 회전판 기본 자리를 −88.9°로 옮기면서 이 사슬을 안 고쳐서, 11/05 손목 D405로 찍은 정면 문틀이 **왼쪽 뒤 59~156°**에 찍혔다(지도와 0.3% 겹침).

**어떻게**: 팔은 대기 자세로 고정하고 **회전판만** 여러 각으로 돌리며 같은 벽 보드를 본다. ①이 풀려 있으면 각 장의 보드 위치를 팔 바닥 좌표로 알고,
보드는 차체에 대해 고정이니 회전판 각 ↔ 보드 위치의 짝에서 **회전판 축 위치(차체 x·y·z)와 영점 오프셋**을 푼다(①과 같은 원리, 고정된 것을 여러 자세에서 보기).
→ 도구 아직 없음([`개발일지-2026-11-05-집안탐색.md`](개발일지-2026-11-05-집안탐색.md) §3.1).

**보정되면 되는 것**: 차체를 안 돌리고 회전판·어깨로 손목 D405를 돌려 사방을 보는 **🔭 둘러보기**를 지도에 바로 얹는다(가상 라이다). 좁은 방에서 제자리 한 바퀴를 대신하고, 돌기 전에 옆에 닿을지 안다.

## ④ 차체 → 지도 — 바닥 HOME 마커 (`home_floor.pdf`, ArUco ID 49, 160mm, 화살표 = 출발 정면)

**무엇을**: 로봇이 방 안 어디에, 어느 방향으로 서 있나(`pose x, y, θ`)의 **절대 기준**.
지금 자세는 Astra 스캔매칭과 IMU로 이어 가며 쌓인 오차를 되돌릴 기준이 없다 — 11/09 따라가기에서 맞춤이 미끄러져(x +0.32m) 엉뚱하게 돌았고, 출발 자리 맞춤 겹침 33%로 접근이 통째로 거절됐다(H3).

**어떻게**: 앞 카메라에 마커가 보이는 순간 네 모서리로 PnP → 카메라↔마커 자세 → 차체 장착값을 거쳐 **마커 기준 로봇 자세**(cm·도 단위). 지도 원점을 마커에 묶으면 볼 때마다 쌓인 오차가 0이 된다. 벽 보드(ID 0~16)와 안 겹치게 49.
→ 도구 아직 없음(검출·지도 고정 코드를 붙여야 함).

**보정되면 되는 것**: 출발·귀환 자리 고정(시연 반복성), 지도 맞춤 실패 때의 복구, 3차(방 안 찾아가 잡기)에서 매 회 같은 원점.
