## 3. 오늘 바뀐 것 (전부 젯슨 배포 완료)

`ros2/tools/space_map.py` `approach_cmd` — 정면을 맞춘 뒤의 짧은 거리를 **지도 길로 가지 않는다**(걸음마다 하는 자리 맞춤이 미끄러져 엉뚱하게 돌았다, 두 번):
- `STRAIGHT_STOP_M = 1.2`: 토마토 짐작 자리 1.2m 앞까지 **엔코더로 곧장** 간다. 짐작이 1.4m 안이면 안 간다. 그 뒤엔 돌지 않고 손목 근접으로 넘긴다(직진 뒤 지도 자세가 낡아 방위를 반대로 쟀다).
- `STRAIGHT_OVER = 1.14`: `step_mm`이 목표보다 12~15% 더 간다(세 번 실측).
- `AHEAD_DEG = 25`: 가서 둘레가 좁아도 토마토가 ±25° 안이면 옆자리로 비켜 서지 않는다.
- 그 너머(짐작 − 1.2 > 1.0m)나 직선 위에 점유 칸이 있으면 예전 지도 길.

`find_cmd` — 한 방향에서만 봤으면(→ '못 찾음'이 되기 직전) **그 방위로 돌아 두 장 더 본다**.
`follow_trials.py` — `--here`(사람이 놓은 자리에서 한 회, 물러나기·돌기 없음), `--sweep`은 ±120°.
`tools/cam_record.py` — 시험 영상. 젯슨: 앞+손목 나란히 5fps. PC: `--pc 1`(전경 USB 카메라, DirectShow 1번). **끝내기 = `<out>.stop` 파일 만들기**(윈도우 백그라운드에서도 파일이 닫힌다). PC 카메라가 검으면 Windows 카메라 앱이 쥐고 있는 것.

## 4. 따라가기 한 회 돌리는 법 (사람이 자리만 놓으면 된다)

```
# PC(백그라운드): 전경 녹화
python tools/cam_record.py "docs/시험기록/영상/follow_here_<날짜>-<회>.mp4" --pc 1
# 젯슨: 앞+손목 녹화 + 한 회
ssh server@100.85.187.87 'cd ~/tomato-picker; V=~/follow_trials/follow-$(date +%Y%m%d-%H%M%S)-<회>.mp4;
  nohup ~/.venvs/vision/bin/python tools/cam_record.py $V >/dev/null 2>&1 &
  timeout 420 ~/lerobot/.venv/bin/python ros2/tools/follow_trials.py --scan --sweep --here; touch $V.stop'
# 끝나면 PC 녹화도: touch "<같은 경로>.stop"
```
놓는 조건: 화분 1.2~1.5m · **둘레 60cm 안에 가구·가방 없음**(Astra 사각) · 토마토는 주행 정면 기준 60~90° 옆.
⚠ `pkill -f cam_record`를 ssh 명령 안에서 쓰지 말 것 — 그 ssh 셸 자신이 걸려 죽는다(오늘 한 번).

## 5. 남은 약점 (따라가기)

1. **출발 자리 맞춤 겹침 < 50%면 접근이 통째로 거절**된다(H3, 화분 2m·TV장 옆). 처방 후보: 맞춤이 안 돼도 앞 카메라에 토마토가 보이면 검출만으로 정면 맞추기 — 미반영.
2. 찾기의 Astra 거리는 실제보다 **0.3~0.5m 멀다**(원인 미조사 — `tomato_ranges`의 20% 백분위가 뒤 배경을 섞는지, 장착값 `x 0.345`가 틀렸는지). 지금은 1.2m 여유로 덮었다.
3. 둘레 60cm 안이 막힌 출발은 스캔이 Astra 무효로 60초씩 기다린다.
4. 영상은 `.gitignore`(`docs/시험기록/영상/`) — PC에만 있다. PM에게 보낼 땐 H1·H2 전경 영상.
