# 개발 노트 — 2026-08-11

하루 종일 **라인 주행의 신뢰성**과 싸웠다. 시작은 "젯슨↔아두이노 통신이 원활하지
않고 모터 움직임을 믿을 수 없다"였고, 끝은 **주행 방식 자체를 갈아엎는 것**
(펄스 뱅뱅 → 저속 연속 + 비례보정)이었다. 그 사이에 펌웨어 v2.1(리셋 원인 자백),
`/diag` 실시간 계측 화면, 지점 정렬 기능이 생겼다.

[2026-08-09 노트](개발노트-2026-08-09.md)와 같은 규칙 — "무엇을 만들었나"가 아니라
**"무엇에 속았고 어떻게 알아챘나"** 를 남긴다.

## 1. 이번에 가장 크게 배운 것

### ① 물리(정지마찰)가 제어 문제로 위장한다

오늘 헤맨 것의 절반이 결국 **메카넘 롤러의 정지마찰** 하나였다.

| 증상 | 오진 | 진짜 원인 |
|---|---|---|
| 정렬을 눌러도 오차가 안 줄어든다 | "보정 부호가 반대다" (화면이 그렇게 말했다) | **로봇이 아예 안 움직인 것.** 멈춘 메카넘은 vy를 줘도 롤러 정지마찰 때문에 옆으로 안 간다 |
| vx=105를 계속 줘도 전진하지 않는다 | 링크/듀티 문제 | 같은 것 — 그 듀티로는 정지마찰이 안 깨진다 |
| 톡톡 한 걸음 크기가 매번 다르다 | 통신 지터 | 슬루+양자화도 있지만, 근본은 정지↔운동 마찰 경계에서 구동하는 것 |

돌파구는 둘 다 **사용자의 관찰**이었다: "살짝 전진 후진하면서 하면 좌우로 조금은
움직여지더라"(→ 정렬 흔들기), "내가 하는 것처럼 움직이면 줄에 비슷하게 가더라"
(→ 저속 연속 주행). **바퀴가 이미 구르고 있으면 정지마찰이 깨져 있어 작은 보정도
그대로 먹는다.** 멈춘 상태에서 큰 펄스가 필요했던 건 제어가 나빠서가 아니었다.

최종 주행 방식:
- **주행 = 저속 연속**(vx ≈ 88 상시) + vy·w **비례보정** + 출발 킥(굴렀으면 즉시 종료)
  + 좌우 톡(정지마찰 유지용, 부호 엄격 교대로 상쇄)
- **정렬 = 펄스 톡톡**(제자리라 여전히 필요) + 전후 흔들기(dither, 같은 이유)

### ② 계측을 먼저 만들면 원인이 스스로 걸어 나온다

`/diag`(SSE 10Hz, 지령 100Hz 샘플링)를 만들자마자:
- **`ok F 50`** — 대시보드에서 예전에 저장한 `base_tuning.json`이 PWM을 50Hz로
  묶고 있었다(코드 기본값 700Hz를 파일이 덮는 구조를 잊고 있었다).
- **acks에 `R`이 두 번** — 튜닝을 두 경로가 중복 푸시하는 경합 발각.
- **재부팅 28회/2분, USB 이벤트 0건** — 리셋이 통신선이 아니라 AVR 자신에게서
  나온다는 결정적 증거.

1초 폴링(`/status`)로는 80ms 펄스도, 이런 패턴도 안 보인다. **관측 주기는 관측
대상보다 촘촘해야 한다.**

### ③ 상태 추측보다 절대 관측 — 어긋나면 스스로 복구되게

지점 번호가 반대로 찍히고(오른쪽 끝인데 "0. 좌측 끝"), 세다가 놓치고, 정렬 중에
저절로 올라갔다. 전부 **추측(진행 방향, 화면 배치)에 의존한 상태 갱신**이 깨진 것.

- 끝점이 어느 쪽인지 = **테이프가 이어지는 방향**(band_left/right_frac)으로 판정.
  진행 방향을 몰라도, 손으로 옮겼어도 맞는 절대 관측. 끝점 위에 서 있기만 하면
  번호가 스스로 확정된다.
- 마커 재무장 = 화면 배치("모든 마커가 중앙에서 멀다")가 아니라 **실제 이동
  거리**(오도메트리). 화면 배치 조건은 지점 간격(375px) < 화면(1280px)이라
  기하적으로 성립 불가능했다 — 그래서 재무장이 죽어 다음 지점을 통째로 못 셌다.
- 그래도 어긋날 때의 탈출구 = [N으로 지정](이동 없이 번호만 정정, 항상 통함).

## 2. 펌웨어 v2.1 — 보드가 왜 재부팅하는지 자백하게 만들기

**증상**: 2분 사이 28회 재부팅. dmesg에 USB 이벤트 0건, 포트 안 끊김(hb_resets=0).
→ 리셋은 AVR 자신에게서. 워치독(=loop 블로킹)인지 브라운아웃(=전원)인지 구분이
필요했다 — 처방이 정반대라서.

### MCUSR은 이 보드에서 못 쓴다 (실측)
부트로더가 MCUSR을 지우고, optiboot처럼 r2에 사본도 안 남긴다(mcusr=0x0,
r2=0xAF ← 쓰지도 않는 상위비트가 켜진 잔여값). 그대로 디코드하면 "WDT BOD EXT
POR 전부"라는 무의미한 답이 나온다.

### 그래서 우리가 직접 흔적을 남긴다
- **워치독을 인터럽트 우선 모드(WDIE|WDE)로**: 첫 250ms 타임아웃은 ISR → .noinit에
  자백(wdtHit + 어느 국면이었는지 wdtPhase) → 다음 250ms에 진짜 리셋.
- **.noinit magic으로 warm/cold**: SRAM은 리셋으로 안 지워지고 전원이 나가야
  깨진다. cold = 전원 문제 확정.
- **lastPhase 국면 추적**(serial/I2C/setHz/stop) → `boot #N warm cause=WDT last=I2C`
  한 줄로 원인+위치가 나온다. 젯슨(motor_link)이 파싱해 원인별 누적을 /diag에 표시.
- **원인 차단도 함께**: `Wire.setWireTimeout(3ms)`(AVR TWI는 버스가 물리면 무한
  대기 → 워치독 1순위 후보), `Wire.setClock(400k)`(applyCurrent 9.5ms→2.4ms —
  100kHz에선 5ms 슬루 틱보다 I2C가 길었다), 명령마다 `wdt_reset()`(F 두 개 =
  delay 200ms), `W` 자가진단 명령(일부러 멈춰 cause=WDT last=test 실증).

### 이 과정의 함정 둘 (재발 주의)
1. **`#if defined(WIRE_HAS_TIMEOUT)` 가드 금지** — arduino:avr 1.8.8엔 그 매크로가
   없어 블록이 통째로 사라진다. 컴파일은 되는데 타임아웃 없는 펌웨어가 조용히 나온다.
2. **흔적 변수는 전부 `volatile`** — 읽는 쪽이 "다음 부팅"이라 컴파일러 눈엔
   죽은 저장으로 보여 최적화로 제거된다(`lastPhase=PH_TEST; for(;;){}` 저장이
   실제로 사라져 last=idle로 나왔다).

굽는 경로: Windows arduino-cli 컴파일 → hex scp → 젯슨 avrdude.
구 펌웨어 백업 = 젯슨 `~/mecanum_v2_backup.hex`.

실전 첫 수확: 주행 중 `cause=WDT last=idle` 1회 포착 — **전원이 아니라 loop
블로킹**이라는 것이 확정됐다(GPIO 배선 전환으로는 안 고쳐지는 종류).
단, boot 카운터가 튀는 것(#16129)은 SRAM 일부 오염 — `cause=`/`last=`만 믿을 것.

## 3. 라인 주행 — 오늘 고친 함정들

### 검출(line_follow)
- **가짜 마커**: 코스 밖 마루 타일이 중간지점(h19~21) 5개 + 끝점 2개로 잡혀 지점
  세기와 오도메트리 원점(가짜 끝점이 latch)을 동시에 무너뜨렸다. → **띠 근접
  필터**. ⚠ 고정 비율(화면 30%)로 했다가 **진짜 끝점을 버렸다**(마커가 커서 중심이
  띠에서 220px). 조건은 크기 기반: `|마커y−띠y| ≤ 띠½두께 + 마커½높이 + 80px`.
- **"테이프 없음"의 이유 보고**: 세 관문(구분 안 됨/화면을 안 가로지름/두께 범위
  밖)마다 사유를 남겨 화면에 표시. 코스 끝에서 띠가 화면 밖으로 나가는 경우를
  색 문제와 구분할 수 있게 됐다.

### 주행 제어(line_drive)
- **복구 수단은 위험 조건에서 잠기면 안 된다**: dy 한계(0.55)가 정렬까지 잠가서,
  크게 벗어나면(246px) 주행도 정렬도 안 됐다. 정렬은 테이프가 보이기만 하면 항상
  가능. 순서 = 분실 → 도달 → **정렬 우회** → 이탈 정지.
- **정렬 발산 오탐**: 판정을 "OFF 구간이면"으로 걸어 50Hz 루프에서 3틱 만에
  "부호가 반대"를 선언(첫 펄스가 끝나기도 전에). → 펄스 OFF→ON 경계에서 한 번만.
- **순간 깜빡임에 버튼 잠김**: preflight에 주행 정지와 같은 유예(0.4s).
- **오버슈트**: 감속을 "마커가 보이는 순간"(반화면)부터 거리 비례로, 도착하면
  **지점 정렬(align_mark)** 로 자동 마무리(마커를 화면 중앙 ±45px에 — 사람이
  [정렬톡톡]+[시간이동 0.1]로 하던 수작업의 자동화). 지나쳤으면 되돌아온다.
- **출발 킥은 정지마찰용이지 가속용이 아니다**: 0.3초 고정이면 지점 간격의 상당
  부분을 킥 속도로 달려 "순항을 낮춰도 여전히 빠르다"가 된다. 굴렀다는 증거
  (오도메트리 25px)가 보이는 즉시 종료.
- **정렬은 지점 번호를 절대 못 바꾼다**: 정렬 펄스·정착 진동으로 마커가 창을
  들락거리며 제자리에서 1→2→3이 됐다. 정렬 중 계수 금지 + 재무장에 최소 이동량
  (120px) 요구. 손으로 밀면 오도메트리도 움직이므로 수동 추적은 유지된다.
- **좌우 톡 부호는 벽시계가 아니라 펄스 수로 교대**: 감속으로 주기를 건너뛰면
  같은 부호가 반복돼(+9/-5) 그 불균형이 곧 dy 표류였다.

### 운영 함정
- **/settings 중복 탭이 설정을 되돌린다**: [적용]은 슬라이더 전부를 보내므로,
  재시작 전 값으로 초기화된 옛 탭에서 누르면 새 값이 옛 값으로 덮인다.
  탭 하나만 쓰고, 값이 안 먹는 것 같으면 먼저 새로고침.
