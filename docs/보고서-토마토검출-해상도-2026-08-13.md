# 토마토 6개 중 2개만 잡히던 문제 — 원인은 추론 입력 해상도 (2026-08-13)

대상: 젯슨 Orin Nano `192.168.0.8`, `tomato-vision` 서비스 (`tools/tomato_vision.py`)
무대: 화분 3개 × 토마토 2개 = **6개**, 고정 USB 웹캠 1280×720

---

## 1. 증상

대시보드 배너와 영상 오버레이가 **`air tomatoes: 3`** 에서 멈춰 있었다. 화면상
초록 박스는 **왼쪽 화분의 2개에만** 붙고, 가운데·오른쪽 화분의 4개는 더 크고
더 밝게 보이는데도 전혀 잡히지 않았다. (3은 HOLD_SEC 유지 때문에 남은 최댓값.)

"멀고 어두운 게 안 잡힌다"가 아니라 **가까운 것만 잡힌다** — 조명 문제가 아니었다.

## 2. 원인

`model.predict()`에 `imgsz`를 주지 않아 **ultralytics 기본값 640**으로 추론하고
있었다. 1280×720 프레임이 640×384로 레터박스 축소되면서 열매 지름이 절반이 되고,
그중 카메라에서 먼 4개가 검출 한계 아래로 내려갔다. 카메라에 가장 가까운 왼쪽
화분 2개만 살아남은 것.

`TV_CONF`(0.10)나 모델 크기는 원인이 아니었다.

## 3. 스윕 결과 (원본 프레임 5장, GT 6개)

`hit` = GT 6점 중 커버한 수, `FP` = GT 근처가 아닌 박스 수.

| imgsz | conf 0.02 | conf 0.05 | conf 0.10 |
|---|---|---|---|
| 640  | 5.2 / FP 0 | 4.0 / FP 0 | **1.2** / FP 0 |
| 960  | 6.0 / FP 0 | 5.2 / FP 0 | 2.2 / FP 0 |
| 1280 | **6.0** / FP 0 | **6.0** / FP 0 | **6.0** / FP 0 |

해상도만 올리면 conf를 건드리지 않아도 6/6이 된다.

### 신뢰도 여유폭 (imgsz=1280)

conf를 0.005까지 내려 모든 후보를 뽑아본 결과:

- 토마토 검출 32건 / 기대 30건, conf 최대 **0.447**
- **오검출 0건** — 사람·박스·로봇팔·빨간 봉이 있는 어수선한 배경에서도 단 하나도 없음
- 32−30 = 중복 박스 2건, 둘 다 conf < 0.02

**박스 개수**(대시보드가 세는 값)를 conf × iou 격자로 확인:

| conf | 0.02 | 0.05 | 0.08 | 0.10 | 0.15 |
|---|---|---|---|---|---|
| 박스 수 (5프레임) | 6,6,6,6,6 | 6,6,6,6,6 | 6,6,6,6,6 | 6,6,6,6,6 | 5,4,5,5,5 |

정확히 6이 나오는 구간은 **0.02 ~ 0.10**. 아래로는 중복 박스, 위로는 누락.
iou(0.4/0.5/0.7)는 결과에 영향 없었다.

## 4. 적용

[tools/tomato_vision.py](../tools/tomato_vision.py):

- `TV_IMGSZ` 신설, **기본값 = 캡처 폭(1280)**. 해상도를 바꿔도 따라가고,
  ultralytics 제약에 맞춰 32의 배수로 반올림한다.
- `TV_CONF` 기본값 **0.10 → 0.05**. 6이 나오는 구간(0.02~0.10)의 중앙이라
  조명이 흔들려도 위아래로 여유가 있다.

## 5. 검증

- 추론 시간 **66ms/frame (15.1 fps)** — `TV_FPS=8` 목표에 여유. 해상도를 4배 올렸지만
  Orin Nano GPU가 감당한다.
- 서비스 재시작 후 `/dev/shm/tomato_status`를 12초간 샘플링: **`air: 6` 연속 유지**,
  좌표 6개가 실제 열매 위치와 일치
  `(472,152) (460,283) (735,165) (717,300) (1002,170) (988,296)`.
- 대시보드 `/video` 실화면: **`air tomatoes: 6  fallen: 0`**, 여섯 개 모두 박스 밀착,
  오검출 없음.

## 6. 남은 것

- `air` 개수는 HOLD_SEC 최댓값이고 `positions`는 현재 프레임이라, 검출이 깜빡이는
  순간 배너 개수와 좌표 개수가 어긋날 수 있다(예: `air: 2`, 좌표 1개). 6/6이
  안정적인 지금은 드러나지 않지만 구조적으로 남아 있다.
- 무대 배치나 카메라 거리가 바뀌면 스윕을 다시 돌리는 게 안전하다 —
  결정적인 변수는 **화면에서 열매가 차지하는 픽셀 크기**다.
