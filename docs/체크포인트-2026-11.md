목표가 아니라 **판정 규약**을 적는 문서다. "됐다"는 말은 여기 적힌 숫자로만 한다.

|---|---|---|---|

| **1차** | 12/15 | 바로 앞 모형 토마토의 모형 줄기 잡기 | 규약 20회 중 **≥10회** |
| **2차** | 1/14 | STM32 엔코더·E-STOP 주행보드 완성 | §2 합격 5항목 전부 |

## 잡기 측정 규약 (1차·3차 공통)

**성공** = 닫은 뒤 **집게값 ≥ 6.0**(빈손 5.0~5.4, 물림 6.2~6.9 — 11/01 실측) **그리고** 사람 눈으로 줄기가 두 손끝 사이에 있음.
둘 중 하나라도 아니면 실패. 화면 오차가 줄어도 안 물렸으면 실패(가는 표적의 가짜 성공, 9/10).

**실패는 넷 중 하나로 적는다** (게인을 만지기 전에 어느 통이 큰지부터 본다):
1. **빈손** — 닫았는데 집게값 < 6.0
2. **엉뚱한 곳** — 꼭지·고리·지지대를 물었다
3. **충돌** — 지지대를 밀거나 화분을 넘어뜨림 → 그 회는 **즉시 중단·실패**
4. **시간초과** — 클릭부터 닫기까지 **60초** 넘김 (11/03 실측 24~48초)

**무대** (매 회 같게):
- 모형 토마토 1개 + 모형 줄기(노란 띠), 열매 높이 30~50cm.
- 시작 자세 `1.6,93.9,115.7,-34.7,6.4`, 줄기까지 110~150mm.
- 매 회 토마토를 옮긴다: 좌우 ±5cm, 앞뒤 ±3cm, 로봇 회전 ±20° 안에서 **주사위로** 정한다(같은 자리면 과적합).
- 조명·배경 고정. 팔은 측정 전 **토크 끄고 10분 쉬게** 한 뒤 시작(밤새 켜 두면 −50mm 처짐, 11/03).

**기록**: 표 한 장 — `회 | 옮김(좌우/앞뒤/회전) | 결과 | 실패 종류 | 소요초 | 집게값`. 영상은 전체 1개.
20회를 **하루에 끝낸다**(날을 나누면 팔 상태가 달라 섞인다). 중간에 코드를 고치면 **처음부터 다시** 센다.

## 1차 (~12/15) — 20회 중 10회

- 규약 그대로. 지금 알려진 병 하나 = 다가가기 위아래 **진동**(빈손 4회의 공통 원인, 11/03) → 게인 0.6 반영했고 미검증.
- 1차 안에서 할 것: ① 게인 0.6 검증 ② 놓기(열기→왼쪽 12mm→빼기) 검증 ③ 실패 4종 분포 보고.
- 하지 않을 것: 차체 주행 개선(2차 보드가 해결), 야외·레일, 여러 그루.

## 2차 (~1/14) — 합격 5항목 ([`stm32-자세보드-목표.md`](stm32-자세보드-목표.md) §2에서 가져옴)

| # | 항목 | 합격 |
|---|---|---|
| E1 | 엔코더 4채널 | 바퀴 손으로 10바퀴 → 카운트 `CPR×10 ± 1`, 4채널 전부, 최고속 누락 0 |
| E2 | 위치 제어 | 1m 사각형 3바퀴 뒤 위치 오차 ≤ 10cm, 각도 ≤ 3° (지도 보정 없이) |
| E3 | 비상정지 | 누르면 바퀴 즉시 정지, **놓아도 잠김**, `X 0`으로만 해제(`S`로는 안 풀림) |
| E4 | 전원 | 팔 + 4바퀴 급역전 100회 + stall 10회 동안 **젯슨·보드 리셋 0**, USB `-71` 0 |
| E5 | 호환 | 젯슨 코드 수정 없이 `/dev/ttyUSB0`로 `V`·`S`·하트비트 그대로, `python tools/stm32_link_check.py` 통과 |

일정: 11월 주문 → 12월 2~3주 납땜·부팅 → 12월 말~1월 초 E1~E5. 기판이 12월 말을 넘기면 2차를 1/31로 미루고 PM에게 **미리** 말한다.

## 3차 (~2/15) — 찾아가서 잡기 10회 중 5회

- 무대: 방 안(실내 평지) 2m 안에 모형 나무 **1그루**, 로봇 출발 위치·방향을 매 회 무작위.
- 한 회 = 🍅찾기 → 정면 → 앞으로(70cm) → 손목 근접(450mm) → **1차 규약의 잡기** → 놓기. **사람 개입 0**, 5분 이내.
- 성공 판정은 1차 규약과 같다. 실패 분류에 **"못 찾음" · "접근 실패(거리 오차 >5cm)"** 두 통을 더한다.
- 10/24 02시 자동 루프가 스캔→찾기→정면→앞으로→손목 근접(494mm)을 **한 번** 이어서 했다(`작업판-2026-10-23.md` §10/24, 정식 보고·판정 기준 없음). 그래서 접근도 3차 규약 안에서 다시 센다. 3차의 본체는 **접근 끝과 잡기 시작을 잇는 것**이다.
- 차체 정밀 이동은 바퀴 톡톡(`base_tap`) 기준 **±5mm까지 가능**하다. 그 이상의 연속 이동 거리 제어는 2차 보드 몫.

## 가상 공간에서 먼저 돌려 본다 (2026-11-03~)

`PYTHONIOENCODING=utf-8 python ros2/tools/checkpoint_sim.py` → [`checkpoint_sim.html`](checkpoint_sim.html)
(브라우저로 열면 3D로 돌려 볼 수 있다 — 탭 1·2·3차, 회마다 ✅/❌·실패 종류·재생 슬라이더). 장치 없이 PC에서 몇 분.

| 차수 | 가상에서 돌리는 것 | 못 보는 것 |
|---|---|---|
| 1차 | 실측 링크 기구학 + 11/02 레시피(pan → 시작 맞춤 → 8mm 전진 → 깊이 75 닫기) + 주사위 옮김 + 카메라 잡음(깊이 σ15·가로 3·세로 8)·표 편차 σ5·처짐 | 서보 토크·전원·조명·YOLO |
| 2차 | **E2만** — 메카넘 4바퀴·엔코더 양자화·미끄럼·반지름/윤거 틀림(추정값)으로 1m 사각형 3바퀴, 요=엔코더/IMU 둘 다 | E1·E3·E4·E5(기판이 있어야 잰다) |
| 3차 | space_map_sim 가짜 방에 화분·줄기·열매를 세우고 scan→find→approach→near→reach **실기 코드 그대로**(장치만 바꿔 끼움) → 1차 잡기 | 위와 같음 + 실제 방의 가구 |

결과(seed 0, 2026-11-03): **1차 9/20 ❌**(빈손 8·엉뚱한 곳 3 — 첫 깊이 σ15mm가 가장 큰 통, 실기 11/03 9/14와 같은 급) · **2차 E2 엔코더 요 0/10 ❌**(각도 6~18° — 윤거 1% 틀림이 1080°에 그대로 쌓인다), **IMU 요 6/10**(각도 0~6°, 바이어스 0.05°/s가 97초에 5°) → 3° 합격은 **IMU 바이어스 0.02°/s 아래 + 윤거 보정**이 있어야 한다 · **3차 6/10 ✅**(접근 실패 2 — `face`가 지도 방위 147°를 한 넛지(2초 상한)로 35°만 돌고 8°씩 여덟 번 더듬다 끝남, 그 뒤 출발 맞춤 거절 / 둘레 0.39m; 충돌 1·빈손 1은 잡기 모델) — **face의 큰 각 회전을 나눠 돌게 고치는 것**이 3차의 첫 일.

같은 날 고친 뒤(**3차 7/10**, 열 번 다 잡기까지 갔다 — 남은 셋은 잡기 모델의 빈손·엉뚱한 곳):
- `turn()` 시간 상한을 각도에 비례(1°당 1/15초 더) — 2초 상한은 정지마찰 보호지 각도 상한이 아니었다. `face`는 한 넛지가 못 채운 **남은 방위**를 마저 돈다.
- `approach_goal`이 **둘레(0.45 + 도착 허용 0.2)가 나오는 자리**를 토마토 둘레 ±90°에서 고른다(나무 자신은 장애물로 안 셈). 상자 모서리 0.3m 옆에 서서 못 돌던 7회.
- 가서 보니 좁으면(가며 지도가 자라 모서리가 드러난다) 새 지도로 **자리를 한 번 더** 고르고, 둘째는 도착 허용을 반으로(0.12m 옆 자리를 '이미 거기'로 치고 안 갔다). 벽 모서리의 나무 6회.
- `checkpoint_sim.py 3 --only 6` — 한 회만 다시 돌린다(회마다 씨앗이 따로). 한 회 ≈ 2분.
- 페이지의 **🎮 직접 조작** 탭(2026-11-04) — 같은 방·같은 토마토 모형에서 사람이 W/S·A/D·Q/E로 차체를 몰고 슬라이더로 팔을 움직인다.
  오른쪽 아래가 손목 D405 시점, 읽기 칸에 줄기 표적까지 앞/옆/위 mm와 **같은 판정 창**으로 "닫으면 잡힌다/빈손/엉뚱한 곳/충돌"이 뜬다.
  모형이 얼마나 그럴듯한지(화분 20cm·줄기 1cm·열매 공 r 3.5cm·띠 = 열매 위 5.5cm) 눈으로 보라고 만든 것 — 틀리면 `plant()`·`FRUIT_R`·`BAND_UP`을 고친다.
⚠ 돌리는 동안 `space_map.py selftest`·`ros_selfcheck`를 같이 돌리지 말 것 — 같은 임시 파일을 건드려 결과가 달라졌다(같은 씨앗인데 4회가 성공↔빈손).

⚠ 모의는 **알고리즘과 기하**를 검증한다. 잡음 σ는 전부 `checkpoint_sim.py` 위쪽 상수고 출처를 주석에 적었다 —
실측이 바뀌면 거기만 고친다. 숫자가 실기와 다르면 모델이 틀린 것이지 실기가 틀린 게 아니다.
