2. 회전판 서보 (STS3215, 팔 버스 ID 7)

2.1 ID 충돌과 변경

같은 ID를 가진 서보 둘이 동시에 대답하면 패킷이 깨져 둘 다 안 읽힙니다. 이 상태에서 "ID 1 → 7"을 보내면 두 서보가 함께 7이 됩니다. 그래서 어깨 서보 케이블을 뽑아 회전판 서보만 버스에 남긴 뒤 lerobot setup_motor로 ID를 7로 바꿨습니다. 케이블을 다시 꽂은 뒤 ID 1~7이 모두 응답했습니다.

3. base_yaw — 회전판을 팔 시스템에 넣기

3.1 설계 결정: 역기구학(IK) 밖의 관절

회전판과 어깨 pan은 둘 다 세로축 회전입니다. 둘을 같이 풀면 같은 목표점에 답이 무수히 많아집니다. 그래서 회전판은 큰 방향(정면·좌·우)을 고르는 관절로 두고, 세밀한 겨냥은 지금처럼 5축 IK와 pan이 맡습니다. 좌표 사슬에서는 차체와 팔 받침 사이에 회전 하나만 끼웁니다.

base_link→base_yaw (revolute, ±85°)→turntable→arm_base→shoulder_pan …→tool0

손목 D405의 손-눈 보정은 팔 받침 기준이라 영향이 없습니다. 영향을 받는 것은 차체에 고정된 Astra처럼 차체 좌표를 쓰는 쪽입니다.

3.3 실기 확인

  • 읽기 정상(−3.4°). 99° 지령은 거절. +15° 지령 후 15.0°에 도착(마지막 지령 직후엔 11.5°로 뒤처져 있어 도착 대기를 넣었습니다).
  • 부호를 바꾼 뒤 0° → +30° 지령, 서보 읽음 29.2°.
  • 확인 필요 사용자 눈으로는 판이 약 5° 덜 돌았습니다. 엔코더가 서보 출력축에 있으니 서보 혼과 회전판 사이 미끄러짐이 의심됩니다. 혼 나사(M3×20) 4개를 확인해야 합니다.

4. 바퀴 — 전원, 배치, 힘

4.1 "다시 꽂아도 안 된다": 모터 드라이버가 대답하지 않음

I²C 타임아웃이 0회라 버스가 물린 것은 아니었고, 0x40 주소에 아무도 대답하지 않는 상태였습니다. 진단용 스케치 두 개를 구워 직접 확인했습니다(굽기 전 원래 펌웨어는 젯슨 ~/mecanum_before_20261022.hex로 백업).

진단결과뜻
I²C 주소 1~126 훑기응답 장치 0개PCA9685가 주소만 바뀐 게 아니라 아예 없는 것처럼 보임
SDA·SCL 전압(내부 풀업 끔)SDA ≈2.6V · SCL ≈0.7V정상이면 쉴드 풀업 때문에 둘 다 ≈5V. 쉴드 쪽 전원이 없음
원인모터 전원 스위치가 꺼져 있었습니다. 켠 뒤 Find PCA9685 OK

모터 시험 도중 아두이노 USB 칩(CH340)이 먹통이 되어(error -110, 이어서 -71) 젯슨에서는 소프트 리셋으로도 살릴 수 없었습니다. USB 케이블을 다시 꽂아 복구했습니다. 첫 시험의 "소리는 나는데 안 돈다"도 같은 전원 문제였습니다.

4.4 옆걸음 부호

배치를 바꾼 뒤로는 vy+ = 왼쪽입니다. 조작대의 "◀ 좌평행 / 우평행 ▶" 버튼이 반대 부호를 보내고 있어 바꿨습니다. 회전(w+ = 좌회전)은 원래 맞았습니다.

8. 교훈 — 증상이 원인을 가리키지 않았던 것

  • "다시 꽂아도 안 된다" = 꽂는 문제가 아니었습니다. I²C 핀 전압을 재 보니 쉴드에 전원이 없었습니다. 소리만 나고 안 도는 것도 같은 원인이었습니다.
  • 로그가 거짓말을 했습니다. "튜닝 재적용 #1"이 찍혔지만 아무것도 보내지 않았습니다. 그 결과 오전의 넛지·한 걸음 시험 결과를 믿을 수 없게 됐습니다. 로그가 아니라 보드가 보고하는 값(?의 MAX_PWM=)으로 확인해야 합니다.
  • 같은 ID 두 개는 조용히 실패합니다. 오류가 아니라 "가끔 응답"으로 보입니다. 새 서보는 반드시 단독으로 물려 ID부터 바꿉니다.
  • 스토퍼가 없으면 소프트웨어 한계는 두 겹이어야 합니다. 서보 EEPROM ±90°(하드)와 소프트웨어 ±85°(거절)를 따로 둡니다.
