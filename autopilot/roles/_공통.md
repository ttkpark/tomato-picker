# 네 역할이 모두 지키는 것 (러너가 각 역할 헌장 뒤에 붙여 읽힌다)

## 1. 이 루프의 성질
- **너의 문맥은 이 사이클로 끝난다.** 다음 사이클은 새 세션이다. 그러니 머릿속에 남긴 것은
  전부 사라진다 — 남길 것은 **파일**에 남겨라: `autopilot/board.py`(작업판), `docs/`, 코드,
  그리고 마지막 요약(일지에 그대로 들어간다).
- **한 사이클에 한 덩이.** 40분 안에 끝나지 않을 일은 쪼개서 작업판에 넣어라.
- 끝내지 못했으면 `board.py note`에 **어디까지 했고 다음 첫 명령이 무엇인지** 적어라.
  "진행 중"만 적는 것은 아무것도 안 적은 것이다.

## 2. 이 로봇의 1번 병 — 크기부터 재라
지령은 나가는데 아무 일도 안 일어난다. 정지마찰·분해능 문턱 아래는 **물리적으로 0**이다.
- 주행: 회전 문턱 w≈90, 진행 문턱≈90 (2026-08-17 실측).
- 팔: STS3215는 0.088°/틱. 그보다 작은 지령은 0. 좌표 유닛은 그런 크기를 **거절**한다.
- **게인을 만지기 전에 그 크기가 실제로 움직이는지부터 재라.**
- 축마다 문턱이 다르다. 한 슬라이더로 두 축을 자르지 말 것.

## 3. 계통 경계 (CLAUDE.md)
- 계산·실측값은 공유, **장치와 상태의 소유권은 ROS**, 웹 서비스에는 안 붙인다.
- `kinematics`·`handeye`·`cartesian`·`eye.EyeConfig`는 라이브러리로 **계속 쓴다**. 다시 짜지 마라.
- 강제 검사 = `python ros2/tools/ros_selfcheck.py`의 [경계] 항목.

## 4. 젯슨 (닿을 때만)
- 팔(`tomato-voice`)·주행(`controller-drive`)·D405(`depth-cam`)·Astra(`astra-cam`)·조작대
  (`click-server`)는 **한 프로세스만** 장치를 연다. 띄우기 전에 충돌하는 것을 끄고,
  **끝나면 원래 켜져 있던 것을 되돌려 놔라**(다음 사이클이 그걸 기대한다).
- 실기를 만졌으면 끝에 **팔을 대기 자세로** 돌리고 집게를 열어 둔다.
- 화분을 넘어뜨린 전례가 있다. 크게 움직이기 전에 현재 자세를 먼저 읽어라.
- 조작대 API가 곧 사람이 쓰는 버튼이다 — **터미널에서만 되는 조작을 새로 만들지 마라.**

## 5. 자체검증 — 숫자는 젯슨에 올리기 전에 PC에서 확인한다
```
python tools/handeye_check.py        # 45종
python tools/eye_check.py            # 60종
python ros2/tools/ros_selfcheck.py   # 70종
python tools/arm_cartesian_check.py  # 33종
```
초록이 아니면 그 위에 아무것도 쌓지 마라.

## 6. 정직
- 안 해 본 것을 "된다"고 쓰지 마라. 일지와 작업판은 **다음 사이클이 사실로 믿는다.**
  거짓 한 줄이 15일을 엉뚱한 데로 끌고 간다.
- 실패는 실패로 적어라. 명령과 출력 몇 줄을 함께 남겨라.
- 추정과 실측을 구분해서 써라("잰 값" vs "짐작").
